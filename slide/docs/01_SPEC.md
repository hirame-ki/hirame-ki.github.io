# 01. 제품 명세

## 1. 한 줄 요약

옵션을 고르면 Claude·ChatGPT·Gemini에서 쓸 수 있는 '수업 슬라이드 제작 스킬' 또는 '프롬프트'를 만들어 주는 무료 웹앱.

## 2. 배경과 결정 과정 (2026-11-20 대화 정리)

### 2-1. 지금 방식과 문제

- **지금 방식**: 캔바 템플릿 링크와 수업자료를 AI에 함께 넣는다. 텍스트 양, 텍스트 박스, 사진 상자, 애니메이션 같은 세부는 AI에 맡긴다. 결과는 템플릿을 바탕으로 한 HTML 슬라이드, 또는 캔바 템플릿을 AI가 직접 수정한 것.
- **템플릿을 쓰는 이유**: 그냥 부탁하면 AI 특유의 어두운 색과 촌스러운 디자인이 나온다.
- **문제**: 캔바·미리캔버스 커넥터(MCP)가 있어야 하고, 매번 템플릿 링크와 자료를 함께 넘겨야 한다.
- **목표**: 이 구조를 단순화해 **다른 선생님들과 공유**한다. 사용자는 수업 디자인을 하나로 고정하지 않고 매번 다양한 템플릿을 쓴다.

### 2-2. 검토한 대안과 판단

| 대안 | 판단 |
|---|---|
| Claude 디자인 시스템 + Slides | 품질은 좋지만 Claude 전용이고 디자인이 하나로 고정된다 → 공유·다양성에 맞지 않음 |
| 템플릿마다 디자인 스킬 만들기 | 디자인 수만큼 만들고 설치해야 해서 공유가 무겁다 → 비추천 (직접 만든 오리지널 테마 묶음을 나눌 때만) |
| 미리캔버스 브랜드 키트 | 랜덤 선택이 아니다. 등록한 양식을 매번 선택 화면에서 직접 고른다. 교사마다 계정·양식 등록·커넥터가 필요 → 공유용으로 무거움 |
| 캔바 링크만 넣는 프롬프트 | 링크는 해당 커넥터가 연결된 AI에서만 읽힌다 → 누구나 쓰기 어려움 |

### 2-3. 결론: "디자인은 매번 바꾸고, 만드는 규칙만 고정"

- **고정**: 슬라이드를 만드는 규칙(글 양·레이아웃·모션·활동·품질 기준) → 스킬 1개 또는 프롬프트.
- **매번 바뀜**: 디자인 참조(템플릿 이미지 2~4장 또는 링크) + 이번 수업 옵션(슬라이드 수 등).
- 디자인 참조 기본값은 **이미지**(어느 AI든 바로 본다). 링크는 커넥터가 있는 사람을 위한 선택지.
- 스킬 형식(SKILL.md)은 Claude·ChatGPT·Gemini 공통이라 파일 하나로 배포할 수 있다 (06_SOURCES).
- 웹앱의 역할: 옵션 선택 → 스킬·프롬프트 생성, 템플릿 갤러리(링크)와 랜덤 뽑기, AI별 설치·연결 안내.

## 3. 사용자와 원칙

- **사용자**: 디지털 도구에 익숙하지 않은 교사를 포함한 누구나.
- **원칙**
  1. 한 화면에 결정 하나. 처음엔 프리셋 하나만 골라도 끝낼 수 있게.
  2. 전문 용어 대신 쉬운 말. 모든 옵션 옆에 ? 칩.
  3. 복사·다운로드 버튼은 크게. 누른 뒤엔 다음에 할 일을 바로 보여 준다.
  4. 결과 품질은 옵션이 아니라 '고정 규칙'과 '엔진'이 책임진다. 어떤 옵션을 골라도 깔끔해야 한다.

## 4. 핵심 개념 (화면 문구에도 그대로 쓴다)

| 개념 | 설명 | 들어가는 곳 |
|---|---|---|
| 기본 설정 | 매번 같은 규칙 (글 양, 레이아웃, 모션, 활동 등) | 스킬 또는 프롬프트 |
| 이번 수업 옵션 | 수업마다 바뀌는 것 (슬라이드 수, 수업 시간, 참조 방식) | '옵션 한 줄' (복사해서 요청에 붙임) |
| 디자인 참조 | 따라 할 디자인 (템플릿 이미지 또는 링크) | 요청할 때 첨부 |

우선순위: 요청에서 직접 말한 것 > 옵션 한 줄 > 기본 설정.

## 5. 사용자 흐름

### 5-1. 처음 한 번 (설치)

1. **AI 고르기**: Claude / ChatGPT / Gemini (여러 개 고를 수 있음)
2. **받을 형태 고르기**: 스킬(추천: 한 번 설치하면 매번 짧게 요청) / 프롬프트(설치 없이 복사·붙여넣기)
3. **프리셋 고르기** → 필요하면 카테고리별 옵션 조정
4. **받기**: 스킬 ZIP 다운로드 또는 프롬프트 복사
5. **설치 안내 따라 하기**: 고른 AI의 단계별 안내 (04 문서)
6. (선택) **커넥터 연결**: 디자인 참조를 링크로 쓰거나, 캔바·미리캔버스에서 직접 수정하고 싶을 때

### 5-2. 매 수업

1. 디자인 참조 준비: 캔바·미리캔버스에서 마음에 드는 템플릿의 표지 1장 + 본문 2~3장을 PNG로 내려받기 (또는 링크 복사)
2. 웹앱의 '이번 수업' 패널에서 슬라이드 수 등을 조정 → **옵션 한 줄 복사**
3. AI에 [수업자료 + 템플릿 이미지 + 옵션 한 줄]을 넣고 "슬라이드 만들어줘"
4. 결과 HTML 저장 → 브라우저로 열어 발표 (F: 전체 화면)

## 6. 화면 구성

### 6-1. 전체 구조

- 상단: 앱 이름, 단계 표시(① AI ② 옵션 ③ 받기), [처음 쓰는 분] 버튼, 도움말
- 본문: 3단계 마법사. [이전]/[다음] 버튼과 단계 표시 클릭으로 이동
- 데스크톱: 오른쪽에 '내 설정 요약' 고정 패널 / 모바일: 화면 아래 시트
- 별도 탭: 템플릿 갤러리, 커넥터 연결 안내, 발표 단축키, 자주 묻는 질문

### 6-2. ① AI 고르기

- AI 카드 3개: 이름, 한 줄 설명, 지원 배지(스킬 / 캔바 링크 / 미리캔버스 링크). 배지 근거는 04 문서 §1 비교표. 공식 로고 대신 텍스트와 중립 아이콘을 쓴다.
- 받을 형태 토글: [스킬] [프롬프트] + ? 칩("어떤 걸 고를까요?" 비교 팝오버)
- 결과물 선택: HTML 슬라이드(기본, 항상 포함) + [캔바에서 직접 수정] [미리캔버스에서 직접 수정] 추가 선택 (02 옵션 O3)
- 여러 AI를 고르면 ③ 받기에서 AI별 탭으로 각각 제공 + [한 번에 받기]

### 6-3. ② 옵션

- 맨 위: 프리셋 카드 4개 (02 문서 §3). 고르면 아래 옵션이 채워지고, 프리셋에서 바꾼 옵션엔 '변경됨' 표시
- 카테고리 탭: 데스크톱은 왼쪽 세로 목록, 모바일은 가로 스크롤 탭
- 옵션 컨트롤: 하나만 고르기 = 세그먼트 칩, 여러 개 고르기 = 체크 칩, 켜고 끄기 = 스위치, 숫자 = 스텝퍼, 글 = 입력 칸
- 모든 옵션 이름 옆 **? 칩** → 팝오버(설명 1~2문장 + [미리보기] 버튼) → **미리보기 모달**
- 미리보기 모달: 16:9 미니 무대에서 **실제 슬라이드 엔진으로** 효과를 재생. [다시 보기], 선택지 바꿔 보기 버튼, [이걸로 선택]
- **느리게 보기** (2026-11-21): 움직임이 요점인 미리보기(모션 그래픽 E1·E2·E3·E5·E6·E7·E10, 테마 G5)는 실제의 0.3배 속도로 재생한다. 무대에 '느리게 보는 중' 꼬리표, 아래에 "이해하기 쉽게 실제보다 3배쯤 느리게 보여 드려요. 수업 화면에서는 훨씬 빠르게 지나가요." 문구, [실제 속도로 보기]↔[천천히 보기] 버튼. 미리보기 문서 안에서만 애니메이션 재생 속도와 타이머를 늦춘다 (엔진·만들어지는 슬라이드는 그대로).
- 고른 결과물(HTML/캔바/미리캔버스)에 맞지 않는 옵션은 숨기지 말고 흐리게 + 이유 한 줄 (예: "캔바 직접 수정에서는 애니메이션을 넣을 수 없어요")
- 요약 패널: 고른 옵션 칩, 예상 분량(스킬 줄 수·프롬프트 글자 수), 경고(예: 프롬프트가 너무 길면 스킬 추천)

### 6-4. ③ 받기

- AI별 탭 → [스킬] 또는 [프롬프트] 결과
  - 스킬: 파일 구조 미리보기, SKILL.md 미리보기(접기), [ZIP 받기] (AI별 구조 자동 적용), 설치 단계 카드
  - 프롬프트: 미리보기, [복사하기], 붙여넣는 곳·결과 저장 방법 카드
- **이번 수업 옵션 한 줄**: 항상 표시, [복사하기]
- 디자인 참조를 링크로 고른 경우: 커넥터 연결 안내 카드를 위로 올려 강조
- [내 설정 링크 복사] (URL 해시) — 동료에게 같은 설정을 공유
- [오프라인 파일로 바꾸기]: AI가 만든 HTML 파일을 끌어다 놓으면 엔진을 파일 안에 넣어 다시 내려받기 (§8-1)

### 6-5. 템플릿 갤러리

- 카드: 템플릿 이름, 출처(캔바/미리캔버스), 분위기 태그, **링크만** (이미지 파일을 직접 올리지 않는다)
- [랜덤 뽑기]: 태그 필터 안에서 하나 추천
- 갤러리 데이터는 index.html 안 JSON 배열. 사용자가 직접 추가·수정하기 쉽게 주석으로 방법을 적어 둔다. 화면에서는 **추천 템플릿**이라 부른다 (운영자가 고른 링크. 사용자가 링크를 모아 주면 넣는다).
- **내 템플릿** (2026-11-21): 같은 화면 맨 위. 이름 + 템플릿 주소 칸과 [등록], 등록한 목록에 [열기]·[이번 수업에 쓰기]·[지우기]. 옵션 G6에 저장된다(브라우저 저장·공유 링크에 포함). [이번 수업에 쓰기]는 ③ 받기의 '내 템플릿'(추천 템플릿은 '템플릿 주소')에 넣고 ③으로 간다.

### 6-6. 처음 쓰는 분 가이드

- 처음 한 번: "AI 고르기 → 옵션 고르기 → 받아서 설치" 3컷
- 매 수업: "템플릿 이미지 받기 → 옵션 한 줄 복사 → AI에 넣기 → 저장해서 발표" 4컷

## 8. 핵심 설계 결정

### 8-1. 슬라이드 엔진 분리 (권장안)

- 생성 슬라이드는 **엔진(CSS·JS)을 jsDelivr로 불러오고**, AI는 테마 변수와 슬라이드 내용만 쓴다.
  - `https://cdn.jsdelivr.net/gh/{계정}/{저장소}@{버전}/engine/slide-engine.css` (js도 같은 방식)
- 이유: AI 출력이 짧아져 잘림·오류가 줄고, 세 AI에서 같은 결과가 나오고, 엔진을 고치면 모든 결과에 반영된다.
- 버전은 태그로 고정(`@v1.0.0`)한다. 호환이 깨지는 변경은 메이저 버전을 올린다. 태그는 GitHub 웹의 Releases 화면에서 만든다.
- 대안 '파일에 내장(오프라인)': 인터넷 없는 교실용 (02 옵션 O4). 웹앱의 [오프라인 파일로 바꾸기]로 처리한다. AI에게 엔진 코드 전체를 다시 쓰게 하지 않는다.
- **확인 필요**: 각 AI의 미리보기 화면에서 jsDelivr 스크립트가 불러와지는지 실제로 테스트한다. 안 되면 안내 문구를 "파일로 저장해서 브라우저로 열기"로 바꾼다.

### 8-2. 디자인은 "그리기"가 아니라 "고르기"

- AI가 CSS를 매번 새로 짜지 않게 한다. 엔진이 전문 디자인 레이아웃 클래스(03 §9)를 제공하고, AI는 **레이아웃을 고르고, 내용을 채우고, 테마 변수를 정한다.**
- 템플릿 느낌은 테마 변수(색·글꼴·모서리·장식)와 20줄 이내의 장식 CSS로 '해석'한다. 템플릿 그래픽을 복제하지 않는다.

### 8-3. 디자인 참조 처리

- 이미지: 색·글꼴 느낌·장식·배치를 읽어 테마 변수로 바꾼다.
- 링크: 커넥터로 페이지 미리보기를 먼저 확인한다. 열 수 없으면(커넥터 없음·권한 없음) **추측하지 말고 템플릿 이미지를 요청**한다.
- 참조 없음: 내장 테마(02 옵션 G5)를 쓴다.
