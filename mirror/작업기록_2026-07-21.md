## 2. 채택된 결정사항

### 서비스명
**생기부돋보기**로 확정 (기획서의 "세특거울"에서 변경). 세특에 한정하지 않도록 본문 문구도 "기록"으로 일반화되어 있음 — 행특·자율·동아리·진로 기록에도 적용 가능한 표현.

### 임베딩 모델: `Xenova/multilingual-e5-small` 채택
- 기획서 3.4 기준(마진 동률이면 가벼운 쪽, 로컬이 비슷하면 로컬)에 따라 실측으로 결정.
- 26명 실 데이터에서 e5-base·bge-m3보다 **복붙 탐지 성능이 뒤지지 않으면서 6배 가볍고 빠름**.
- 판단 근거: 데이터의 8-gram 글자 겹침을 "정답"으로 삼아 각 모델의 분리도(d)·상위 10쌍 적중률을 비교. 상세 수치는 `test/score-result.json` 참고.
- 드롭다운에 e5-base·bge-m3도 비교용으로 남겨둠.

### 점수 체계: 하이브리드 + 문장 단위 + 강건 통계
절대 임계값(예: "0.85 넘으면 위험") 방식은 실측에서 실패로 확인됨 — 한 학급 기록은 애초에 서로 닮은 상태로 출발하므로 고정 선 하나로는 학급마다 전원 위험/전원 안전으로 갈림. 최종 채택 방식:

1. **표현 유사도 (z)** — 반 전체 평균 벡터를 뺀 뒤(공통 주제 성분 제거) 코사인 유사도 계산 → **중앙값·MAD 기반 강건 통계**로 z 환산. (평균·표준편차 대신 중앙값을 쓴 이유: 복붙 쌍 자신이 잣대를 부풀려 자기 점수를 깎아 먹는 것을 방지)
2. **글자 겹침 (%)** — 연속 8글자(8-gram) containment. 그대로 베낀 정도의 직접 측정.
3. **문장 단위 비교** — 기록 전체를 통째로 비교하면 "한두 문장만 베낀 경우"가 나머지 문장에 희석되어 묻힘. 그래서 문장으로 쪼개 **가장 닮은 문장 쌍**도 별도로 찾고, 전체 기준 z와 문장 기준 z 중 **더 큰 쪽**을 그 쌍의 최종 점수로 사용.
4. 두 기준(z, 글자 겹침) 중 **하나라도 넘으면** "확인 필요"로 표시. 표에 근거(글자/표현/둘 다) 표시.

**기본값**: 표현 유사도 z ≥ **2.5**, 글자 겹침 ≥ **8%**. 둘 다 "정답"이 아니라 출발점이며, 학급 상태에 따라 슬라이더로 조정하도록 안내함 (해석 모달에 근거 서술).

**검증 결과** (test 폴더 실측, `validate-v2.mjs`— scratchpad에서 실행, 프로젝트에는 미포함):
- 문장 단위 도입 전: 복붙군(글자 겹침 상위 10쌍) 중 임베딩 상위 10위 안에 든 것은 5/10
- 문장 단위 + 강건 z 도입 후: 복붙군 15쌍 중 z 상위 15위 안에 13/15 (상위 12위까지는 전부 복붙군)

### 엑셀 양식 열 구성
**학년 | 반 | 번호 | 내용** (이름 열 없음 — 실명을 파일·결과·CSV 어디에도 남기지 않기 위한 의도적 설계). 이름 열을 추가해도 인식은 됨. 학년·반이 없어도 번호만으로 동작.

### 엑셀 읽기/쓰기: 외부 라이브러리 없이 직접 구현
세특(생기부 기록)이 서드파티 스크립트를 거치지 않도록, ZIP 처리(`makeZip`/`readZip`, CRC32 직접 구현)와 XML 파싱을 브라우저 기본 기능(`DecompressionStream`, `DOMParser`)만으로 구현. 위치: index.html 내 "2. 엑셀(.xlsx) 읽고 쓰기" 섹션.

**주의**: 실제 엑셀/한셀이 저장한 파일은 `<x:row>`처럼 **네임스페이스 접두사**를 붙이는 경우가 있음 → `tags()` 헬퍼로 `getElementsByTagNameNS` 우선 사용, 접두사 없는 파일은 폴백. 이 버그는 실제 26명 엑셀 파일로 테스트하다가 발견 (자체 생성한 양식 파일만으로는 발견 못 했을 것).

### 개인정보 원칙
- 기록 내용은 어디로도 전송되지 않음(로컬 임베딩). 저장도 하지 않음(localStorage는 모델 다운로드 여부 플래그만 저장, 기록 내용은 저장 안 함).
- 헤더 배지 + 좌측 패널 하단 안내문 + 사용법 모달에 반복 명시.

## 4. 이번 세션에서 고친 버그 (재발 방지용 기록)

1. **엑셀 네임스페이스 접두사 미인식** — 실제 엑셀/한셀 파일이 `<x:row>`처럼 저장하는데 접두사 없는 태그명으로만 찾다가 0행 파싱됨. `getElementsByTagNameNS` 우선 사용으로 해결.
2. **`.btn.block`과 결과 카드용 `.block` 클래스명 충돌** — 분석 시작 버튼이 활성화되면 흰 배경(`.block`의 `background:var(--card)`)이 파란 배경(`.btn`)을 덮어써서 **흰 바탕에 흰 글씨**가 되어 버튼이 안 보였음. `.btn.wide`로 클래스명 분리하여 해결. (증상이 "비활성일 땐 보이고 활성화되면 안 보인다"였는데, 처음엔 `:disabled` opacity 문제로 오진하여 헛수고함 — Puppeteer로 실제 렌더링 픽셀을 찍어보고서야 원인 특정)
3. **`:disabled` 상태에서 `opacity` 사용 시 흰 글씨가 흐려짐** — opacity 대신 배경·글자색 자체를 바꾸는 방식으로 변경.

**교훈**: 화면 관련 버그는 추측으로 고치지 말고 Puppeteer로 실제 렌더링을 찍어서 확인할 것. `look.mjs`, `rules.mjs`, `flow.mjs` 패턴 재사용 가능 (scratchpad에 있었음, 필요시 재작성).

## 5. 테스트 방법 (재현용)

프로젝트에는 자동화 테스트 파일이 없음(단일 HTML 원칙 유지). 이 세션에서 검증에 쓴 스크립트는 모두 세션 scratchpad(`C:\Users\User\AppData\Local\Temp\claude\...\scratchpad\`)에 있었고 세션 종료 시 사라짐. 다시 필요하면 아래 패턴으로 재작성:

- **순수 함수 단위 테스트**: `index.html`의 `<script type="module">` 내용을 파일로 추출 → Node에서 `import()` (DOMParser는 `@xmldom/xmldom`으로 폴리필 필요, 엑셀 XML 파싱 테스트 시)
- **실제 엑셀 파일 테스트**: `test/테스트 엑셀.xlsx`를 `readXlsx()`에 직접 통과시켜 26명 파싱 확인
- **모델 벤치마크**: `@huggingface/transformers` npm 패키지로 Node에서 직접 실행 (브라우저 CDN과 별개로 로컬 실행 가능)
- **UI 전체 흐름**: Puppeteer + 결정적 스텁 임베딩 모델(문자 3-gram 해시 벡터)로 실제 모델 다운로드 없이 빠르게 렌더링 확인. 스텁 응답 시 **CORS 헤더 필수** (`access-control-allow-origin: *`) — 안 그러면 CDN import가 조용히 실패함.
