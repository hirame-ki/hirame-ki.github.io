## 1. 표현 점검 탭

결과 화면 위에 탭 두 개(`유사도 점검` / `표현 점검`)를 두고, 두 번째 탭에 규칙 기반 국어 점검기를 넣었다.
같은 입력(왼쪽 패널)을 공유하되 **임베딩 모델을 전혀 쓰지 않으므로, 분석 시작을 누르지 않아도 붙여넣는 즉시 결과가 나온다.**

점검 유형 5가지:

| 유형 | 내용 |
|---|---|
| 맞춤법 | 되/돼, 왠/웬, -(으)로서/로써, 율/률, -이/-히, 자주 틀리는 낱말 사전 |
| 띄어쓰기 | 의존명사(수·때·것·뿐·만큼·대로), 중·등·및, -지 않다, 쉼표 |
| 서술 방식 | 명사형(~함)과 평서형(~다) 종결 혼용, 150자 넘는 문장, 마침표 누락 |
| 기재 주의 | 2026 기재요령 입력 불가 항목 14종 (아래 4장) |
| 분량 | NEIS 글자수 계산기와 같은 방식으로 센 바이트 수 · 한도 1,500 / 900 선택 |

부가 기능: 유형별 필터 알약, 본문 밑줄 + 마우스오버 설명, CSV 내보내기, 인쇄/PDF.

## 2. 왜 이 방식인가 (설계 근거 고정)

### 외부 맞춤법 API(부산대·네이버)를 쓰지 않은 이유
품질은 그쪽이 훨씬 좋다. 하지만 기록이 외부 서버로 나가는 순간 이 도구의 전제("데이터가 기기 밖으로 안 나감")가 무너진다.
CORS 때문에 Worker 중계도 필요해져 유사도 쪽에서 일부러 피한 구조가 되살아난다. 비공식 API 약관 문제도 있다. → **탈락.**

### 로컬 ML 교정 모델을 쓰지 않은 이유
한국어 맞춤법 교정은 임베딩과 달리 seq2seq 생성 모델이라 수백 MB급이고, transformers.js로 쓸 만한 ONNX 배포본이 사실상 없다.
채택 모델(e5-small, 약 120MB)보다 무거운 걸 얹는 셈. → **탈락.**

### 규칙 기반으로 좁게 간 이유
용량 0, 완전 로컬, 단일 HTML 원칙 유지. 대신 **오탐이 곧 신뢰 손실**이라고 보고 범위를 좁혔다.
유사도 결과를 "확인 필요"라는 조심스러운 톤으로 잡아 뒀는데, 맞춤법에서 틀린 지적이 몇 번 나오면 도구 전체의 신뢰가 깎인다.
그래서 **문맥을 봐야 판단되는 항목은 일부러 뺐다**: 되/돼 일반형, 던지/든지, 지향/지양, 결재/결제, 열/렬, -(으)로서/로써 일반형.
놓치는 쪽(재현율 손해)이 잘못 잡는 쪽(정밀도 손해)보다 낫다는 판단.

## 3. 실측으로 조정한 것 (`test/테스트 엑셀.xlsx` 26명)

처음 규칙 그대로 돌렸을 때 기록당 0.6건이 걸렸는데, 그중 상당수가 잡음이었다. 두 가지를 고쳤다.

1. **‘등’ 띄어쓰기 규칙 → `갈등과`를 `갈 등과`로 잘못 잡음.**
   앞 음절 한 글자만 보고 걸러서 생긴 문제. 두 음절 낱말 사전(`갈등·평등·고등`…)으로 거르고,
   **앞쪽 40자 안에 쉼표·가운뎃점이 있을 때만** 의존명사로 보도록 바꿨다(열거 문맥 신호).

2. **긴 문장 기준 120자 → 150자.**
   실제 문장 길이 분포를 재 보니 중앙값 69자, 90% 118자, 95% 136자였다.
   120자로 잡으면 26건 중 13건이 걸려 잡음이 된다. 150자면 상위 2~3%만 걸린다.

**조정 후 결과: 26건 중 지적 4건, 전부 "150자 초과 문장" — 오탐 0건.**
(이 표본은 문장이 정제되어 있어 실제 맞춤법 오류가 애초에 없었다. 오탐률 확인용으로만 유효한 수치.)

## 4. 바이트 계산 · 기재 주의 — 외부 기준에 맞춤

두 가지를 바깥 기준에 맞췄다. 처음엔 임의로 잡았던 값이라 실제와 어긋나 있었다.

### 4.1 바이트 계산 — 나이스(NEIS) 글자수 계산기 기준

교사들이 실제로 대조하는 <https://hjh010501.github.io/neis-counter/> (저장소: `hjh010501/neis-counter`, 단일 `index.html`)의
계산식을 읽고 맞췄다. **문자별 규칙:**

| 문자 | 바이트 |
|---|---|
| 한글(음절·자모) | 3 |
| 영문·숫자·공백·탭·ASCII 문장부호 | 1 |
| 줄바꿈 `\n` | 2 (`\r`은 0) |
| 수학기호·그리스문자·**가운뎃점(·)**·**곡선따옴표(‘’“”)** | 1 |
| 그 밖의 문자(한자·℃·→·※ 등) | 3 |

가운뎃점과 곡선따옴표를 1바이트로 세는 것은 그 계산기가 **의도적으로 넣은 규칙**이다(코드 주석에 명시). 세특에 자주 쓰이는 문자라 영향이 크다.
고치기 전 우리 계산(`>0x7F면 3`)은 이걸 3으로 세어 과다 집계하고 있었다.

**한 가지 일부러 다르게 둔 것:** 그 계산기는 한자·℃·→·※ 같은 문자를 **9바이트**로 센다.
계산을 여섯 갈래(english/korean/number/onebyte/threebyte/space/line)로 나눠 더하는 구조인데,
이 문자들이 어느 갈래의 `replace`에도 걸러지지 않아 다섯 갈래에 중복으로 남는다(1+3+1+3+1=9). 명백한 버그로 보여 **3으로 뒀다.**
→ **3으로 가기로 결정함**(2026-07-22). 특수기호는 애초에 기재요령상 쓰지 않는 것이 원칙이라 실무에서 부딪힐 일이 드물다.
   사이트와 숫자를 똑같이 맞추고 싶어지면 `neisBytes`의 마지막 `n += 3` 한 줄만 고치면 된다.

**검증**: 사이트 계산식을 Node로 그대로 포팅해 실 데이터 26건과 대조 → **26/26 완전 일치**.
문자 단위 대조에서도 위 표의 "일부러 다른" 항목 말고는 전부 일치.

**한도도 바뀌어 있었다.** 사이트 표 기준(2026 고교학점제 전면 도입):
자율·동아리·**진로(2,100→1,500)**·교과세특 = 1,500Bytes / **개인별세특(행특) 1,500→900Bytes**.
드롭다운을 `1500 / 900` 두 개로 바꿨다(기존 1500/2100/3000은 근거 없는 값이었음).

### 4.2 기재 주의 — 옆 프로젝트의 금지 목록을 그대로

`C:\Users\User\Desktop\코딩\hirameki\student-report\index.html`(생기부 초안 작성 도우미)의
`FORBIDDEN` 상수 = **2026 학교생활기록부 기재요령 절대 입력 금지 항목**을 그대로 옮겨 왔다.
두 도구가 같은 목록을 보게 해 두면 지침이 바뀔 때 같이 고치면 된다.

옮긴 항목: 대회·수상 / 자격증 / 소논문·연구보고서 / 어학·인증시험(토익·토플·텝스·토스·오픽 등) / 모의고사·전국연합 /
해외활동 / 출간·특허·장학금 / 부모·친인척 지위 / 대학·기관·상호명 / 학교명·재단명·축제명 / K-MOOC·MOOC·KOCW /
방과후학교 / 영재교육 / 특수기호(♦▶★ 등).

**옮기지 않은 것**과 이유:
- **괄호·따옴표 금지** — 원본은 AI에게 주는 작성 지침이라 강하게 잡은 것이고, 실제 NEIS 입력에서 괄호는 흔하다. 잡음이 너무 커서 뺐다.
- **학생 이름 금지** — 입력 양식에 이름 열이 없는 것이 이 도구의 설계라 탐지 대상이 아니다.
- **불필요한 영어 약칭** — 대중적 약칭인지 아닌지는 규칙으로 판단할 수 없다.

**오탐 하나를 잡았다**: `학원` 규칙이 "대학원 진학"을 걸었다. `(?<![대과])학원`으로 앞 글자를 보게 고침.
`[가-힣]{2,6}(?:고등학교|중학교)`는 띄어쓰기가 방패가 되어 "인근 초등학교"는 안 걸리고 "한빛고등학교"만 걸린다(확인함).

## 5. 무시할 문구 (어제 보류했던 기능 — 이번에 넣음)

`작업기록_2026-07-21.md` 6장에 "제안만 하고 반영 안 함"으로 남아 있던 항목. **수동 등록 방식으로만** 구현했다.

### 동작
- 왼쪽 패널 3번 칸에 한 줄에 하나씩 문구 등록 → **글자 겹침(8-gram containment) 계산에서만** 제외
- 재분석 없이 즉시 반영 (`recomputeLex()` — 임베딩은 그대로 두고 겹침만 다시 셈)
- 결과의 겹침 매트릭스 아래에 **＋ 제안 칩**: 여러 학생이 함께 쓴 문구를 찾아 후보로 보여 줌. 누르면 등록
- 나란히 보기에서 등록한 문구는 **회색 + 취소선**으로 표시 (무엇을 빼고 봤는지 보이게)

### 설계 판단
- **표현 유사도(z)에는 적용하지 않는다.** 그쪽은 반 평균 벡터를 빼는 방식으로 이미 공통 성분을 걷어내고 있고,
  문장에서 일부를 도려내면 임베딩이 오히려 망가진다.
- **자동 제외는 여전히 하지 않는다.** 프로그램이 공통 문구를 알아서 빼면 진짜 복붙한 문장이
  "다들 쓰는 표현"으로 분류되어 조용히 사라질 수 있다. 도구는 후보만 제안하고, 무엇을 뺄지는 교사가 고른다.
- 문구는 **빈칸으로** 치환한다(`split(ph).join(' ')`). 그냥 지우면 앞뒤가 붙어 **없던 8글자 덩어리가 생긴다.**
- 4글자 미만 문구는 무시한다. 짧으면 기록 곳곳이 지워져 겹침이 전부 0이 된다. 안내문에 "기록의 N%를 제외 중"을 표시해
  과하게 등록했을 때 바로 알 수 있게 했다.

### 제안 알고리즘
8-gram의 문서빈도(df)를 세어 **전체의 50% 이상 & 최소 3명**이 가진 덩어리만 남기고, 연달아 이어지는 구간을 하나의 문구로 잇는다.
긴 것부터 남기고 그 안에 포함되는 조각은 버린 뒤, df 높은 순으로 최대 6개.

> **알아 둘 것**: 학급의 절반 이상이 실제로 같은 문장을 복붙했다면 그 문장도 제안 목록에 오른다.
> 칩에 문구 전문이 그대로 보이므로 교사가 읽고 판단하는 것이 방어선이다. 누르기 전에 읽어야 한다.

### 검증
5명 표본(공통 문구 + 1쌍만 진짜 복붙)으로 확인:

| | 확인 필요 쌍 |
|---|---|
| 등록 전 | **10쌍** (공통 문구 때문에 무관한 쌍도 38~40%로 걸림) |
| 제안 칩 1회 클릭 후 | **1쌍** (진짜 복붙 1-2만 100%로 남음, 나머지는 0%) |

Puppeteer로 분석→제안→클릭→재계산→나란히 보기까지 전 과정 확인.
모델 없이 UI 흐름만 볼 때는 **결정적 스텁 임베딩**(문자 3-gram 해시 벡터)을 요청 가로채기로 주입하면 된다.
이때 **CORS 헤더(`access-control-allow-origin: *`)를 반드시 넣어야** CDN import가 조용히 실패하지 않는다.

## 6. 명칭 변경 — 생기부거울 → **생기부돋보기**

유사도 전용 도구였을 때 붙인 이름이라, 표현 점검이 붙고 나니 범위가 맞지 않았다.

- **거울 → 돋보기**: "비춰 준다"보다 "자세히 들여다본다"가 지금 기능 전체(유사도 + 맞춤법·띄어쓰기·서술 방식·기재 주의·분량)를 덮는다.
  형제 도구 `규정나침반`과 짜임(개념 + 도구 은유)도 맞다.
- **부제**: `생기부 유사도 점검 도우미` → `생기부 점검 도우미`. 사실 범위를 좁히고 있던 건 이름보다 이 부제였다.
- **파비콘**: 겹친 사각형 두 개(거울) → 돋보기. 브랜드 색(`--brand`, 청록)으로 맞췄다. 16px에서도 형태가 유지되는지 확인함.
- **헤더 로고**: 세로 막대 하나였던 자리를 **선 그림 돋보기**로 교체(파비콘과 같은 그림).
  안쪽 두 줄은 "기록을 들여다본다"는 뜻. `.logo .mark` 안에 인라인 SVG, 색은 `currentColor`로 받는다.
- 바뀐 곳: `<title>`·헤더 로고·메타 태그·저작권 주석·사용법 모달·인쇄 머리말,
  그리고 **내려받는 파일 이름**(`생기부돋보기_입력양식.xlsx`, `생기부돋보기_확인필요쌍_*.csv`, `생기부돋보기_표현점검_*.csv`).

> **주의**: 이름이 받침 있는 말(거울)에서 받침 없는 말(돋보기)로 바뀌었다. 일괄 치환하면 **조사가 틀어진다**
> (`생기부거울은` → `생기부돋보기은`). 치환 후 `은/는`, `이/가`, `을/를`, `과/와`를 훑어볼 것. 실제로 한 군데 났다.

## 7. 검증 방법 (재현용)

`index.html`의 `<script type="module">` 본문을 뽑아 두 가지로 나눠 확인했다. 스크립트는 모두 scratchpad에 있었고 세션 종료 시 사라진다.

- **규칙 단위 테스트**: 14장(`const CAT =` ~ `function computeLint`) 구간만 잘라 `.mjs`로 만들면 DOM 없이 Node에서 그대로 import된다.
  "걸려야 하는 문장 23개 / 걸리면 안 되는 문장 14개"를 넣고 양쪽 다 통과하는지 확인. → **실패 0**
  - 걸리면 안 되는 쪽 예: `실수 없이`, `고등학교`, `규칙대로`, `사실대로`, `말뿐인`, `공부에 열심이다`, `조사 대상`, `일등으로`, `반응률`, `그중에서도`,
    `대학원 진학`, `인근 초등학교`, `학교 축제`, `문학·역사·철학`
- **바이트 계산 대조**: 사이트(`neis-counter`)의 계산식을 그대로 Node로 옮겨 우리 `neisBytes()`와 실 데이터 26건·문자 단위로 대조.
- **실 데이터**: `.xlsx`의 `xl/sharedStrings.xml`만 꺼내 `<x:t>` 텍스트를 훑으면 된다.
  **주의**: 여기도 네임스페이스 접두사(`x:t`) 때문에 `<t>`로만 찾으면 0건이 나온다(어제 겪은 것과 같은 함정).
- **UI**: Puppeteer로 빈 상태 / 분량 초과 / 한도 변경 / 필터 토글 / 탭 전환 / 유사도 탭 회귀를 확인하고 전체 스크린샷을 찍었다.
- **CSV**: 헤드리스에서는 `blob:` 다운로드가 파일로 저장되지 않는다(양식 다운로드 버튼도 마찬가지 — 기존 코드 문제가 아님).
  `URL.createObjectURL`을 가로채 Blob 내용을 직접 읽는 방식으로 확인했다.

## 8. 구현 메모

- 코드 위치: `index.html` **14장 "표현 점검"** (기존 13장 뒤, 파일 끝). 유사도 쪽 코드는 수정하지 않았다.
- 규칙 표현: `rule(cat, why, re, fix, guard)` / 사전형은 `dict(cat, why, map, guard)`.
  `guard(m, text)`로 오탐을 걸러 낸다(예: `수` 규칙에서 `실수` 제외, `-이/-히`에서 `열심이다` 제외).
- 종성 판단 헬퍼 `jong(ch)` / 관형형 판단 `isAdn(ch)` — 의존명사 띄어쓰기 판정에 쓴다.
- **문장 나누기를 유사도 쪽 `splitSentences()`와 공유하지 않는다.** 그쪽은 짧은 조각을 앞 문장에 붙여 잡음을 줄이는데,
  종결어미 혼용·문장 길이를 볼 때는 그 병합이 판단을 흐린다(붙어 버리면 혼용을 못 잡음). 그래서 `rawSentences()`를 따로 뒀다.
- 겹치는 지적은 앞선 것·긴 것 우선으로 하나만 남긴다(밑줄이 겹쳐 깨지는 것 방지).
- 입력이 바뀌면 `lintDirty()`가 캐시를 버리고 250ms 뒤 탭 뱃지 숫자를 다시 센다. `refreshParse()` 한 곳에서만 부른다.
