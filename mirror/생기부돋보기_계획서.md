## 0. 서비스 명칭 (추천)

개발 진행 전 하나를 확정. 브랜드는 기존 도구들(규정나침반·협의회 도우미)과 톤을 맞춤.

| 후보 | 뜻 / 느낌 | 비고 |
|---|---|---|
| **세특거울** | 내가 쓴 세특을 비춰 겹치는 부분을 보여준다 | 직관적, 발음 쉬움. **1순위 추천** |

> 이 문서는 **세특거울**을 기준 명칭으로 작성. 확정 시 이대로, 변경 시 명칭만 치환.

> **[확정 · 2026-07-22] 최종 명칭은 `생기부돋보기`.**
> 세특거울 → 생기부거울 → **생기부돋보기** 순으로 바뀌었다. 아래 후보 표는 처음 검토 기록으로만 남겨 둔다.
> - `세특 → 생기부`: 세특뿐 아니라 행특·자율·동아리·진로 기록에도 쓰이므로 범위를 넓혔다.
> - `거울 → 돋보기`: 유사도 전용 도구에서 **맞춤법·띄어쓰기·서술 방식·기재 주의·분량까지 훑는 점검 도구**로 커졌다.
>   "비춰 준다(거울)"보다 "자세히 들여다본다(돋보기)"가 지금 기능 전체를 덮는다. 형제 도구 `규정나침반`과 짜임(개념 + 도구 은유)도 맞다.
> - 부제도 `생기부 유사도 점검 도우미` → `생기부 점검 도우미`로 좁힘을 풀었다.

## 1. 무엇을 만드는가 (한 줄)

교사가 반 전체 세특(교과 세부능력 특기사항)을 붙여넣으면, 학생 간 **문장 유사도를 정량 수치로 계산**해 "복붙 세특" 위험 구간을 표로 짚어주는 브라우저 완결형 웹 도구.

> **[갱신 · 2026-07-22] 범위가 넓어졌다.** 유사도 전용 도구에서
> **생기부 기록 전반을 점검하는 도구**가 되었다. 화면은 탭 두 개로 나뉜다.
>
> | 탭 | 하는 일 | 모델 |
> |---|---|---|
> | 유사도 점검 | 학생 간 겹침(표현 유사도 + 글자 겹침) | 임베딩 필요 |
> | 표현 점검 | 맞춤법 · 띄어쓰기 · 서술 방식 · 기재 주의 · 분량 | **불필요**(규칙 기반, 즉시) |
>
> 대상도 세특에서 생기부 전체(행특·자율·동아리·진로)로 넓혔다. 그래서 이름도 세특거울 → 생기부돋보기.

## 2. 왜 챗봇이 아니라 전용 도구인가 (설계 근거 고정)

- 챗봇 유사도 판정은 인상 평가 → 재현성·정량성 없음.
- 임베딩은 문장을 벡터화해 **코사인 유사도(0~1)** 를 계산 → 표·임계값으로 객관화 가능.
- 세특은 개인정보 → 외부 서버 전송 자체가 부담. **브라우저 로컬 처리**가 핵심 셀링포인트.
- 판정기가 아니라 **점검 보조 도구**. "여기 겹치니 확인하라"까지만. (같은 수행평가는 자연히 유사할 수 있음 → UI에 명시)

## 3. 기술 전략: 임베딩 엔진 선택

### 3.0 확정 사항 (아키텍처)
규정나침반의 **단일 HTML + 순수 JS(빌드 없음) 뼈대는 그대로 계승**하되, 임베딩 엔진은 NVIDIA API가 아니라 **브라우저 로컬 실행(transformers.js)** 로 간다. 세특의 개인정보 민감성 때문에 데이터가 네트워크를 한 번도 타지 않는 구조가 필수.

이 결정으로 규정나침반이 겪었던 **CORS → Cloudflare Worker 중계 구조가 불필요**해진다. (규정나침반은 브라우저→Worker→NVIDIA 경로였음. 생기부돋보기는 브라우저 내에서 완결.)

### 3.1 기본 방침
**로컬(브라우저 내 실행) 확정.** 무료 API(NVIDIA)는 로컬이 품질 미흡일 때만 쓰는 최후 폴백.
- 개인정보: 데이터가 기기 밖으로 안 나감 (최대 강점, 완전 보장).
- 비용/한도: API 키·40 RPM 제한·CORS·Worker·약관 회색지대 전부 무관.
- 배포: 각 교사 키 발급 불필요, 링크만 열면 작동.

### 3.2 테스트 대상 (성능 비교)
아래 로컬 모델을 동일 샘플로 비교. **한국어 세특 문장** 기준 성능이 관건 (영어 위주 MTEB 순위와 다를 수 있음). transformers.js로 ONNX 실행 가능한 모델이어야 함.

| 구분 | 모델 | 실행 방식 | 특징 |
|---|---|---|---|
| 로컬 A | **bge-m3** (BAAI) | transformers.js / ONNX | 다국어 강세, 한국어 양호. 자체호스팅 품질·비용 균형 우수로 널리 추천됨. 용량 다소 큼 |
| 로컬 B | **multilingual-e5-base** (intfloat) | transformers.js / ONNX | 다국어 검색 표준, 경량(로딩 빠름). query/passage 프리픽스 필요 |
| 로컬 C | **multilingual-e5-small** (intfloat) | transformers.js / ONNX | 초경량. 로딩 속도 최우선일 때. 품질은 B보다 낮음 |
| (폴백) | nemotron-3-embed-1b (NVIDIA) | 무료 API | 로컬이 전부 미흡할 때만. Worker·BYOK 필요해져 최후 수단 |

> 참고: gte-multilingual-base(Alibaba, 70+ 언어)도 ONNX 변환본이 있으면 후보. 로컬 A/B/C가 미흡할 때만 확장.
> transformers.js 실행 가능 여부(ONNX/quantized 배포본 존재)는 착수 시 Hugging Face에서 최신 확인 필요.

### 3.3 테스트 방법 (거창하지 않게)
`test/` 폴더에 검증 세트 구성:
- **유사쌍 5개**: 일부러 표현만 바꿔 쓴 세특 (예: "적극적으로 참여" ↔ "능동적으로 참여함") → **높은 점수 나와야 정상**
- **상이쌍 5개**: 주제가 확실히 다른 세특 → **낮은 점수 나와야 정상**
- 판정: 유사쌍 평균 > 상이쌍 평균 이며 그 간격(마진)이 넓을수록 우수.
- 각 모델의 점수 분포를 표로 출력해 육안 비교 → 마진 가장 큰 모델 채택.

### 3.4 채택 기준
1. 유사/상이 마진이 가장 큰 모델.
2. 동률이면 브라우저 로딩 시간이 짧은(모델 용량 작은) 쪽.
3. 로컬이 API와 비슷하면 **무조건 로컬 채택** (개인정보·배포 이점).

## 4. 처리 흐름 (파이프라인)

```
[교사 입력]           [전처리]              [임베딩]            [계산]              [출력]
학생별 세특 텍스트  →  이름/번호 분리     →  각 세특을 벡터화  →  전체 쌍 코사인    →  유사도 매트릭스
(표 붙여넣기 or       공백/특수문자 정리     (택1: 로컬 모델)     유사도 N×N 계산      + 위험쌍 하이라이트
 CSV 업로드)          빈 항목 제외                              임계값 필터          + 문장 나란히 비교
```

- 전 과정 브라우저 내 실행. 네트워크 전송 없음(로컬 모델 기준).
- 모델 파일은 최초 1회만 다운로드 후 캐시.

## 5. UI / 디자인 요구사항

### 5.1 전체 인상
"한 줄로 흘러내리는 페이지"가 아니라 **갖춰진 웹앱** 느낌. 상단 헤더 + 좌우 분할 레이아웃 기반.

### 5.2 레이아웃 (권장 구조)
```
┌─────────────────────────────────────────────────────┐
│  헤더: 로고(생기부돋보기) · 모델선택 · 도움말 · 개인정보안내 │
├───────────────┬─────────────────────────────────────┤
│  좌측 패널     │   우측 메인 영역                       │
│  (입력/설정)   │   (결과 대시보드)                      │
│               │                                     │
│  - 세특 입력   │   [상단 요약 카드]                    │
│    (표 형태)   │    총 인원 / 위험쌍 수 / 최고 유사도   │
│  - 임계값      │                                     │
│    슬라이더    │   [유사도 매트릭스] N×N 히트맵         │
│  - 모델 선택   │    셀 클릭 → 하단 상세                │
│  - [분석 시작] │                                     │
│               │   [상세 비교] 두 세특 나란히,          │
│               │    겹치는 표현 강조                   │
└───────────────┴─────────────────────────────────────┘
```
- 좌측: 입력·설정 고정 패널. 우측: 결과가 열리는 대시보드.
- 결과 미생성 시 우측은 빈 상태 안내(placeholder) 카드.
- 모바일: 좌우 분할을 상하 탭 전환으로 폴백.

### 5.3 색 / 폰트 (피로도 최소화)
- **배경**: 순백(#FFFFFF) 대신 아주 옅은 회색·미색 톤(예: #F7F8FA) → 장시간 응시 시 눈부심 완화.
- **주조색**: 차분한 저채도 블루/그린 계열(신뢰감). 고채도 원색 금지.
- **강조/위험**: 위험 유사쌍은 붉은 계열이되 **채도 낮춘 톤**(선홍색 X → 벽돌/코럴 톤). 안전은 저채도 그린.
- **히트맵**: 유사도에 따라 저채도 → 고채도 단색 그라데이션(무지개색 금지, 색맹 접근성 고려).
- **폰트**: **궁서체 금지.** 본문은 가독성 높은 산세리프 — Pretendous/Pretendard, 없으면 시스템 산세리프(맑은 고딕 등) 폴백. 숫자·표는 등폭 성향 폰트로 정렬감.
- **행간·여백**: 표 셀 여백 넉넉히, 본문 line-height 1.6 내외.

### 5.4 신뢰감 요소
- 헤더 또는 첫 화면에 **"입력한 세특은 이 브라우저 안에서만 처리되며 어떤 서버로도 전송되지 않습니다"** 배지 상시 노출.
- "이 도구는 점검 보조입니다. 유사도가 높다고 반드시 문제는 아닙니다"를 결과 상단에 명시.

## 7. 기술 스택 (제안)

| 영역 | 선택 | 비고 |
|---|---|---|
| 구조 | **단일 HTML + 순수 JS (빌드 없음)** | 규정나침반과 동일. GitHub Pages 바로 배포 |
| 임베딩 실행 | **transformers.js** (Hugging Face, CDN) | 브라우저 내 ONNX 모델 실행. WebGPU 가속 시 빠름. **네트워크로 세특 전송 없음** |
| 중계 서버 | **불필요** | 규정나침반의 Cloudflare Worker 구조 제거(로컬 임베딩이라 CORS 무관) |
| 유사도 계산 | 자체 코사인 함수 | 벡터 정규화 후 내적 |
| 히트맵 | Canvas 또는 경량 라이브러리 | 셀 수 많을 때 Canvas 유리 |
