# 연수 전자서명 시스템 v6

**서명 이미지는 기관 구글 드라이브에, 그 외 모든 데이터(기관명·구성원·연수·서명기록)는
공용 Supabase 프로젝트에** 저장하는 하이브리드 구조입니다. 학교뿐 아니라 교육청·연수원 등
**어떤 기관이든** 시트를 만들 필요 없이 곧바로 사용할 수 있습니다.

## v6 구조

```
[GitHub Pages]                [Supabase (공용 1개)]        [각 기관의 구글 드라이브]
 index.html          ←──→     기관명·구성원·연수·         code.gs (이미지 업로드 전용,
 (공통 웹페이지)               서명기록 텍스트              스탠드얼론, 최초 1회 배포)
                               (org_key로 기관 구분)         · 서명 PNG만 여기 저장
```

- **웹페이지(이 저장소)**: 관리자가 업데이트하면 모든 기관에 자동 반영
- **Supabase(공용)**: 기관명 / 부서 / 구성원 / 연수 / 서명기록 텍스트 — 관리자 웹 패널에서 전부 관리, 시트 없음
- **code.gs(기관별)**: 서명 이미지를 그 기관의 구글 드라이브에 저장하는 역할만 — 최초 1회만 배포하면 끝
- 연결고리: 웹페이지 접속 시 기관의 **Apps Script 배포 URL**을 입력(최초 1회) → 그 배포 ID가 Supabase에서 기관을 구분하는 키(`org_key`)가 됩니다

이전 v5(구글 시트 바인딩)보다 기관 관리자가 할 일이 더 줄었습니다 — 시트를 만들거나
초기설정을 실행할 필요 없이, 스크립트 배포 → 웹페이지 연결 → 관리자 패널에서 정보 입력,
이 세 단계면 끝입니다.

## 최초 준비 (저장소 관리자 — 한 번만 하면 됨)

1. **Supabase 프로젝트 준비**: 기존에 운영 중인 프로젝트(무료 플랜)에 `supabase-schema.sql`
   전체를 SQL Editor에서 실행 ("Run without RLS" 선택 — RLS는 의도적으로 안 씁니다.
   대신 테이블 직접 접근을 전부 막고 RPC 함수로만 접근하도록 설계되어 있습니다)
2. `index.html` 상단 `<script>` 안의 `SUPABASE_URL`, `SUPABASE_ANON_KEY`를
   실제 프로젝트 값으로 채우기 (Project Settings → API 에서 확인)
3. GitHub Pages로 배포 (Settings → Pages → Branch: `main`)

## 기관 관리자 설치 방법 (약 3분, 최초 1회)

1. [script.google.com](https://script.google.com) → **새 프로젝트** (시트 필요 없음)
2. 기본 코드를 지우고 `code.gs` 내용 전체 붙여넣기 → 저장
3. [배포] → [새 배포] → 유형: **웹 앱**
   - 실행 계정: **나** / 액세스 권한: **모든 사용자** ← 반드시!
   - 최초 1회 권한 승인 창이 뜨면 계정 선택 후 허용
   - [배포] 후 **웹 앱 URL** 복사
4. 서명 웹페이지(GitHub Pages 주소)에 접속 → 복사한 URL 붙여넣기 → [연결하기]
5. 헤더의 ⚙️ **관리자** 버튼 → 관리자 비밀번호 최초 생성 →
   **기관 설정**(기관명·부서목록·안내문·색상) / **구성원 관리** / **연수 관리** 순으로 입력
6. 연결 완료 후 표시되는 **공유 링크와 QR**을 구성원에게 안내

> ⚠️ 배포는 **딱 1회**면 충분합니다. 이후 화면·기능 업데이트는 웹페이지에 자동 반영되며,
> 기관명·구성원·연수 정보도 전부 웹페이지의 관리자 패널에서 관리하므로 이 코드를 다시
> 손댈 일이 없습니다.

### 사본(시트)으로 배포하고 싶다면

기관 담당자에게 "script.google.com에서 새 프로젝트 만들기"부터 안내하기 부담스럽다면,
아래처럼 **코드가 이미 담긴 구글 시트 사본**을 만들어 배포하는 방법도 있습니다
(시트는 안내문 역할일 뿐, 웹앱 동작 자체는 스탠드얼론일 때와 동일합니다):

1. 구글 시트 새로 만들기 → [확장 프로그램] → [Apps Script] → 기본 코드를 지우고 `code.gs` 전체 붙여넣기 → 저장
2. 시트로 돌아와 새로고침 → 메뉴 **[🖊️ 전자서명 관리]** → **[📖 사용설명서 만들기]** 클릭
   → `📖 사용설명서` 탭이 생성되며, 배포·초기설정 순서가 전부 정리되어 있습니다
3. 이 시트의 **사본**(파일 → 사본 만들기)을 각 기관에 배포 — 사본을 받은 담당자는
   `📖 사용설명서` 탭만 보고 따라 하면 됩니다

## 주요 기능

- 📝 3단계 서명: 연수 선택 → 부서/성명 선택 → 캔버스 서명
- 🔒 중복 방지: 서버(Supabase UNIQUE 제약) 차단 + 기기(브라우저) 잠금 이중 안전망
- 🖼️ 서명 이미지: 기관 자신의 구글 드라이브에 PNG로 저장, 웹페이지에서 URL로 불러와 표시
- 🖨️ **서명등록부 출력**: 웹페이지 [서명결과 출력] → 2인 1행 표(부서·성명·서명 이미지) + 서명률 → 브라우저 인쇄/PDF 저장
- ⚙️ **관리자 패널**: 연수 등록/수정/삭제, 구성원 등록/수정/삭제, 기관 설정(기관명·부서목록·안내문·대표색상)을 전부 웹페이지에서 처리
- 📱 공유 링크 + QR: 연결 완료 시 자동 생성 (헤더의 🔗 버튼으로 언제든 다시 열기)
  - 링크는 배포 ID만 담은 압축형(`?s=...`)으로 만들어지고, 무료 단축 서비스(da.gd → clck.ru 순 시도)로 **단축 주소**가 자동 생성되면 QR도 그 짧은 주소로 만들어져 인식이 잘 됩니다 (단축 실패 시 압축형으로 자동 대체)

## 관리자 패널 (헤더 ⚙️ 버튼)

- **연수 관리**: 연수명·대상(드롭다운)·시간(시작~종료)·날짜·활성여부 등록/수정/삭제 (개수 제한 없음)
- **서명 기록**: 연수·날짜 선택 → 조회 → 이름·부서·시각 목록에서 개별 삭제 (실수로 등록된 서명 등 정리용)
- **구성원 관리**: 부서·성명 등록/수정/삭제 — 여기 등록된 명단이 서명 화면의 부서·이름 선택 목록이 됩니다.
  - 목록은 **부서별로 묶어서** 표시 (먼저 등록한 부서가 위)
  - 부서는 기존 부서 중 드롭다운으로 선택하거나 "새 부서 직접 입력"으로 추가
  - 구성원 추가 시 여러 명을 줄바꿈·쉼표로 구분해 **한 번에 일괄 등록** (엑셀 이름 열 복사-붙여넣기 지원)
  - 부서 제목줄의 **[부서명 수정]** 버튼으로 그 부서 전원의 부서명을 일괄 변경
- **기관 설정**: 기관명, 안내문, 대표 색상(색상 선택기)
- 관리자 비밀번호는 최초 1회 웹페이지에서 직접 생성하며, 서명결과 출력 비밀번호로도 같이 쓰입니다

## 자동화 (GitHub Actions — 핑 · 아카이브 · 알림)

⚠️ **이 프로젝트는 `hirame-ki.github.io` 저장소 안에 다른 프로젝트(ssamverse 등)와 함께
`/sign` 하위 폴더로 존재합니다.** GitHub Actions는 **저장소 루트**의 `.github/workflows/`만
인식하므로, 아래 파일들은 `sign/` 폴더 안이 아니라 **저장소 최상위**에 올려야 합니다:

```
(저장소 루트)/.github/workflows/sign-ping.yml
(저장소 루트)/.github/workflows/sign-archive.yml
(저장소 루트)/.github/scripts/sign-run-archive.mjs
```

또한 저장소가 여러 프로젝트와 시크릿을 공유하므로, 이름이 겹치지 않도록 **`SIGN_` 접두사가
붙은 전용 시크릿**을 사용합니다 (기존에 다른 프로젝트가 쓰고 있을 `SUPABASE_URL` 등을
건드리지 않기 위함).

### 2. 동작 방식

- **`sign-ping.yml`** — 3일마다 Supabase에 가벼운 요청을 보내 무료 플랜의 "1주일 미사용 시 자동 일시정지"를 방지. 매번 sentinel 파일에 커밋을 남겨 GitHub의 "60일 무커밋 저장소는 예약 워크플로 자동 비활성화" 정책도 함께 회피. (ssambus 프로젝트는 이미 다른 워크플로가 주기적으로 깨우고 있다면 이 워크플로는 이중 안전장치일 뿐이며, 없어도 무방합니다.)
- **`sign-archive.yml`** — 매주 월요일, `sign-run-archive.mjs` 실행:
  1. Supabase에서 전체 기관 목록(`org_key`, `apps_script_url`) 조회
  2. 기관별로 `archive_old_signatures()` 호출 → 60일(기본값) 지난 서명 기록을 돌려받으며 동시에 Supabase에서 삭제
  3. 돌려받은 기록을 그 기관의 Apps Script로 전송 → 그 기관 자신의 드라이브에 엑셀로 저장
  4. 저장이 끝나면 `code.gs`가 **그 기관 스크립트를 배포한 계정 이메일로 자동 알림 메일** 발송 (건수 + 백업 파일 바로가기 링크 포함). 특정 주소로 받고 싶으면 `code.gs`의 `NOTIFY_EMAIL` 상수에 이메일을 지정
- 보관 기간은 `sign-archive.yml`의 `ARCHIVE_DAYS` 값(기본 60)만 바꾸면 조정 가능
