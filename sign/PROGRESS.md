## 2026-07-21 세션 작업 내역 (미서명 표기 제거 + 서명 기록 조회 달력)

### 1) 서명등록부 출력: 미서명자 칸을 빈칸으로

- `cellHtml()`(index.html)에서 서명 기록이 없는 사람의 서명란에 찍히던
  `<span class="pd-unsigned">미서명</span>`을 **빈 문자열로 변경**. 손으로 채워 넣거나
  그냥 비워 두는 실제 사용 방식에 맞춤.
- 하단 요약표의 "미서명 N명" 집계 문구는 **그대로 유지**(사용자와 합의). `.pd-unsigned` CSS
  규칙도 남겨 둠 — 되돌리려면 위 한 줄만 원복하면 됨.

### 2) 관리자 → 서명 기록 탭: 기록이 있는 날짜를 달력에 표시

- **배경**: 날짜를 하나씩 찍어서 조회해 봐야 그날 기록이 있는지 알 수 있어 불편했음.
- 브라우저 기본 `<input type="date">`의 팝업 달력은 **날짜에 표시를 넣을 수 없어**(스타일링
  불가) 자체 달력 UI로 교체함. 값은 기존과 동일하게 hidden `#recDate`에 `YYYY-MM-DD`로
  들어가므로 `fetchAdminRecords()` / 출력 로직은 손대지 않음.
- 새 RPC **`get_signature_dates(p_org_key, p_title, p_from, p_to, p_pin)`**
  (`supabase-schema.sql`) — 기간 내 서명이 있는 날짜 + 인원수를 `{date, count}` 배열로 반환.
  PIN 검증은 `get_signature_records`와 동일(`needPin`), revoke/grant 목록에도 등록함.
- 달력 동작: **선택한 연수 기준**으로 기록이 있는 날짜에 브랜드 색 점 + `title="서명 N명"`,
  오늘은 색 강조, 선택일은 채운 원, 일요일은 빨강. 월 이동(‹ ›) 시 그 달을 조회하고
  `연수명|YYYY-MM` 키로 캐시(`recCalCache`)해 중복 호출 방지. 기록 삭제 성공 시 캐시 비움.
  연수 셀렉트 변경 시(`onRecTrainingChange`) 달력이 열려 있으면 다시 조회.
- 데모 모드(`API_URL` 없음)에서는 달력은 정상 동작하되 점 표시만 없음.
- 관련 함수: `setRecDate` / `toggleRecCal` / `recCalMove` / `recCalPick` / `loadRecCalMarks` /
  `renderRecCal`, CSS는 `.cal-trigger`·`.cal-pop`·`.cal-day` 계열.
- ⚠️ **사용자가 직접 해야 함**: Supabase SQL 편집기에서 `supabase-schema.sql` 재실행
  (전부 `create or replace`라 재실행 안전). 새 함수만 실행할 경우
  `grant execute on function get_signature_dates(text, text, date, date, text) to anon, authenticated;`
  도 같이 실행해야 함. 실행 전까지는 달력은 뜨지만 점 표시가 나오지 않음.
- ⚠️ 브라우저 실측 미확인(코드 상 구현만 완료) — 실제 화면에서 달력 열림/점 표시 확인 필요.

## 2026-07-13 세션 작업 내역 (연수별 서명 가능 시간대 강제)

- **배경**: QR을 공유받은 사람이 교육에 참석하지 않은 사람에게 다시 전달해, 미참석자가 서명하는
  사례가 있었음. PIN(현장 코드) 방식도 검토했으나 "QR을 전달하는 사람이 PIN도 같이 알려줄
  가능성이 높고, 정작 현장 참석자만 입력 단계가 늘어 불편해진다"는 이유로 기각 — **연수 진행
  시간대에만 서명을 허용**하는 방식으로 확정.
- 원래 연수 등록 폼의 "연수 시간" 입력(`tfTimeStart`/`tfTimeEnd`)은 `content` 텍스트에
  녹여 넣어 화면에 안내 문구로만 보여주는 용도였고 실제로 강제하진 않았음 — 이번에 이 값을
  `trainings.start_time`/`end_time` 전용 컬럼으로 분리 저장하고 실제 게이트로 사용하도록 변경.
- **DB (`supabase-schema.sql`)**:
  - `trainings`에 `start_time time`, `end_time time` 컬럼 추가 (둘 다 NULL이면 기존과 동일하게
    하루 종일 서명 가능 — 기존 데이터 호환).
  - `save_training()`에 `p_start_time`/`p_end_time`(text, 'HH:MM') 파라미터 추가. 시그니처가
    바뀌므로 재배포 시 오버로드 충돌 방지용 `drop function if exists`를 먼저 실행하도록 함.
  - `submit_signature()`에 서버 시각(`now() at time zone 'Asia/Seoul'`) 기준 시간대 검사 추가 →
    범위 밖이면 `timeBlocked:true` 반환. **클라이언트가 보낸 시각이 아니라 서버 시각으로 검사**하는
    것이 최종 방어선 (기존 UNIQUE 제약을 통한 중복 방지와 같은 철학).
  - `get_page_data`/`_trainings_json`에 `startTime`/`endTime` 필드 추가해 프런트에 노출.
- **프런트 (`index.html`)**:
  - 연수 목록에서 시간대를 벗어난 연수는 흐리게 표시(`.time-blocked`)하고 안내 문구로 대체,
    클릭 시 새 모달(`modalTimeBlocked`)로 안내 — 서버의 `timeBlocked` 오류도 기존 범용 오류
    모달로 이미 처리됨(추가 분기 불필요).
  - 관리자 폼 라벨 "연수 시간(선택)" → "서명 가능 시간(선택 · 설정하면 이 시간에만 서명 가능)"으로
    변경해 이제는 단순 안내문이 아니라 실제 제약임을 명시.
  - 편집 시 시간 입력란 프리필을 기존의 `content` 텍스트 역파싱 대신 `startTime`/`endTime`
    전용 필드에서 직접 가져오도록 변경 (더 안정적).
- **검증 완료**: 사용자가 실제 Supabase에 `supabase-schema.sql`을 재실행하고 서비스 화면에서
  정상 동작 확인함 (시간 미설정 연수는 종일 허용 / 범위 밖 연수는 흐리게 표시+모달 차단 / 범위
  안에서는 정상 서명 / 관리자 수정 시 기존 시간 값 프리필 모두 확인).

## 2026-07-13 세션 작업 내역 (3) — 매일 자동갱신 공유 QR (미참석자 원격 서명 방지)

- **배경**: 위 1번(시간대 제한)을 적용해도, 같은 연수 시간대 안에 카톡 등으로 QR/링크를 전달받은
  미참석자가 원격으로 서명하는 건 못 막는다는 점을 논의 끝에 확인. "개인별 접속 링크"(신원 도용
  방지용)도 검토했으나, "그 자리에 실제로 있었는지"는 여전히 검증 못한다는 한계가 같아 기각.
  최종적으로 **공유 QR/링크 자체를 매일 자동 갱신**하는 방식으로 결정 — 배포 방식(카톡방에 QR
  한 장 공유)은 그대로 유지하면서, 예전에 유출된 QR은 다음 날부터 무효화되도록.
- **DB (`supabase-schema.sql`)**:
  - `institutions`에 `qr_rotate_daily`(모드 토글, 기본 false) / `qr_secret`(기관별 랜덤 비밀값,
    클라이언트에 절대 노출 안 됨, `pgcrypto`의 `gen_random_bytes`로 생성) 컬럼 추가.
  - `_qr_token_for(org_key, date)`: `qr_secret + 날짜`를 sha256 해시해 "오늘자 토큰"(앞 10자)을
    계산하는 내부 헬퍼.
  - `get_page_data`/`submit_signature` 양쪽에 토큰 검사 추가 — 페이지 진입 시점과 실제 서명 제출
    시점 이중으로 최종 방어. 관리자는 PIN으로 우회 가능(캐시된 adminPin 전달 시 토큰 없이도 통과).
  - `get_share_token(org_key, pin)` 신규 RPC — 관리자가 공유 모달을 열 때 오늘자 토큰을 요청
    (매일갱신 모드가 아니면 PIN 없이도 통과, 모드일 때만 PIN 검증).
  - `update_org_settings`/`get_admin_data`에 `qrRotateDaily` 필드 추가.
  - ⚠️ **배포 중 겪은 문제**: Supabase는 `pgcrypto`를 `public`이 아닌 `extensions` 스키마에
    설치해두는데, `_qr_token_for`에 `search_path = public`만 지정해서 `digest()` 함수를 못 찾는
    오류(`42883`) 발생 → `search_path = public, extensions`로 수정해 해결.
    (이 교훈: Supabase에서 pgcrypto 함수를 쓰는 SECURITY DEFINER 함수는 search_path에
    `extensions`를 꼭 포함시켜야 함 — `gen_random_bytes`가 테이블 컬럼 기본값에서는 문제없이
    동작한 것은 SQL 편집기 세션 자체의 기본 search_path에는 이미 extensions가 포함되어 있기
    때문이고, 함수 내부의 고정 search_path와는 별개임)
- **프런트 (`index.html`)**:
  - 관리자 패널 [기관 설정] 탭에 "공유 QR 방식" 라디오 2개(항상 고정 / 매일 자동 갱신) + 취지
    설명 문구 추가.
  - 매일 자동 갱신 모드에서 공유 링크는 `&d=오늘자토큰`이 붙고, 하루 지나면(또는 토큰이 다르면)
    접속 시 전체화면 "이 QR/링크는 만료됐어요" 게이트 화면으로 차단(`#gateExpired`).
  - 공유 모달(`showShareModal`)은 열 때마다 `get_share_token`으로 오늘자 토큰을 새로 받아오도록
    비동기화 — 매일갱신 모드면 PIN 모달이 뜨고(캐시된 adminPin 있으면 자동 통과), 확인 후 오늘자
    QR/링크 표시 + "매일 자정 자동 갱신" 안내 문구.

   - **그 외 전부**(기관명·부서·구성원·연수명/설명/날짜·연수 등록·수정·삭제·서명기록 텍스트·
     관리자 PIN·안내문·대표색상)는 **기존에 운영 중이던 Supabase 프로젝트 `ssambus`**에
     테이블을 추가해 처리 (기관들이 `org_key`로 구분되는 멀티테넌트 공용 DB)
   - 결정 배경(용량 계산, 새 계정 생성 검토 후 기각한 이유, 1개월 vs 2개월 보관 논의 등)은
     이번 세션 대화 로그 참고. 결론: **기존 프로젝트 재사용으로 결정**, ssambus/exam 둘 다
     여유 용량이 넉넉해(둘 다 500MB~1GB 중 0.3GB만 사용 중) 별도 계정 불필요.

## 검증 상태

- `code.gs`·`index.html` 인라인 스크립트 문법 검증 통과, HTML id/onclick 참조 정합성 확인.
- **Supabase 백엔드는 원격(curl/Node)으로 엔드투엔드 검증 완료** (2026-07-07): 기관 등록 →
  PIN 최초 생성/재생성 거부 → 기관 설정 → 구성원/연수 등록 → 공개 페이지 조회 → 서명 제출 →
  중복 차단(UNIQUE) → 등록부 PIN 잠금/조회 → 잘못된 PIN 거부, 테이블 직접 접근 차단까지 전부 통과.
  ⚠️ 이때 테스트 기관 `ZZTEST_delete_me`가 DB에 남아 있음 — 아래 정리 SQL 실행 필요.
- **보안 패치 이력**: Supabase는 default privileges로 새 함수에 anon 직접 실행권한을 자동
  부여하므로 `REVOKE ... FROM public`만으로는 부족했음 → `from public, anon, authenticated`로
  회수하는 패치를 라이브 DB에 실행 완료, `supabase-schema.sql` 원본에도 반영됨.
  (이 교훈: Supabase에서 함수 잠글 때는 반드시 anon/authenticated에게서 직접 REVOKE)
- **브라우저 렌더링/클릭 테스트는 여전히 못 함** (Chrome 확장 미연결). 데모 모드 포함 UI 흐름,
  그리고 Apps Script 이미지 업로드(구글 쪽)는 실제로 안 돌려봄.

  ⚠️ **ssambus 프로젝트는 이미 다른 워크플로가 주기적으로 깨우고 있음을 확인함** (2026-07-08,

  그대로 사용.

### ⚠️ 배포 토폴로지 정정 (2026-07-08) — 매우 중요

처음엔 `sign/`이 자체 GitHub 저장소가 될 거라 가정하고 워크플로 파일을 `sign/.github/...`에
만들었으나, **실제로는 `hirame-ki.github.io`라는 하나의 저장소 안에 `/sign`, `/ssamverse` 등
여러 프로젝트가 하위 폴더로 같이 존재**하는 구조임이 확인됨 (사용자가 지금까지 파일을 GitHub
웹 UI로 직접 업로드하는 방식으로 운영 중, git 연동 아님). 이에 따라:
- 워크플로/스크립트 파일은 `sign/` 안이 아니라 **저장소 루트**의 `.github/workflows/`,
  `.github/scripts/`에 올려야 함 (GitHub Actions는 저장소 루트만 인식)
- 시크릿 이름은 다른 프로젝트(ssamverse 등)와 겹치지 않도록 **`SIGN_` 접두사**로 변경:
  `SIGN_SUPABASE_URL`, `SIGN_SUPABASE_ANON_KEY`, `SIGN_SUPABASE_SERVICE_ROLE_KEY`
  (기존에 저장소에 이미 `SUPABASE_URL`/`SUPABASE_ANON_KEY`/`GROQ_API_KEY`가 다른 프로젝트용으로
  등록되어 있는 것을 발견 — 이름 충돌·오용 방지 위해 구분함)
- 로컬 파일도 `sign/.github/workflows/sign-ping.yml`, `sign-archive.yml`,
  `sign/.github/scripts/sign-run-archive.mjs`로 이름 변경 완료 (업로드 시 저장소 루트의
  `.github/...`로 옮겨서 올려야 함 — `sign/` 접두사 없이)

### 실제 배포·디버깅 과정에서 겪은 문제들 (2026-07-08, 전부 해결됨)

1. YAML `name:` 필드에 `[sign]` 형태로 대괄호를 썼다가 YAML 문법 오류 발생
   (`[`는 flow sequence 시작 문자라 뒤에 텍스트가 오면 파싱 실패) →
   `"sign: 워크플로명"` 형태(따옴표로 감싼 문자열)로 수정.
2. Secrets를 `SIGN_` 접두사 없이 시도 → 이미 다른 프로젝트가 쓰는 `SUPABASE_URL`과 이름이
   겹쳐 "already exists" 에러 → `SIGN_SUPABASE_URL` 등으로 새로 등록.
3. `archive` 워크플로가 `SUPABASE_URL / SUPABASE_SERVICE_ROLE_KEY 환경변수가 필요합니다`로 실패
   → `SIGN_SUPABASE_SERVICE_ROLE_KEY`가 애초에 등록 안 되어 있었음 → 등록 후 해결.
4. `ping` 워크플로가 curl exit code 3(URL 형식 오류)로 실패 → `SIGN_SUPABASE_URL` 값이 비어있거나
   손상되어 있었던 것으로 추정 → Update로 값 재입력 후 해결.
5. **최종적으로 핑·아카이브 워크플로 둘 다 성공 확인 완료** (2026-07-08, 사용자 확인).
   GitHub Actions 자동화(핑/아카이브/알림) 구축이 완전히 끝난 상태.

## 추가 기능: 서명등록부 출력 형식 선택 (2026-07-08)

- **서명률 미포함 시 요약 표(`pd-summary`, 대상/서명/미서명 인원수 + 진행률 바) 전체를 렌더링하지
  않음** — 퍼센트 줄만 숨기는 게 아니라 표 자체를 없앰.
- **페이지 여백 버그 수정**: 기존엔 모든 페이지가 "요약표를 위한 여백 확보용" 행 수(12/15행)로
  고정되어 있어, 여러 페이지짜리 문서에서 마지막이 아닌 페이지도 실제 용지 하단까지 못 채우고
  일찍 다음 페이지로 넘어가는 문제가 있었음 → 1차로 **꽉 채우는 행 수**(15/18행)로 전체를 배치한
  뒤, 서명률 표시가 켜져 있고 계산된 실제 마지막 페이지에 요약표를 붙일 여백이 없을 때만 그
  마지막 페이지 분량만 **여백 확보용 행 수**(12/15행, 기존과 동일)로 다시 나눔. 서명률 미포함이면
  애초에 여백 확보가 불필요하므로 모든 페이지가 끝까지 꽉 참. Node로 0~150명 다양한 조합에 대해
  인원 번호 중복·누락 없음을 시뮬레이션 검증함(브라우저 실측은 아님).
- **미리보기 화면 "닫기" 버튼 동작 변경**: 기존엔 메인 화면으로 바로 나갔으나, 이제 이미 받아온
  서명 기록(`pendingPrintRes`)을 유지한 채 "인쇄 형식 선택" 모달로 되돌아가 형식을 바로 다시
  조정할 수 있음(서버 재조회 없음). 형식 모달의 "취소"는 기존처럼 메인 화면으로 완전히 나감.
- ⚠️ Chrome 확장 미연결로 이번에도 **실제 인쇄 미리보기 화면은 육안으로 확인 못함** — 페이지네이션
  행 수 상수(`ROWS_FIRST_FULL`/`ROWS_NEXT_FULL`/`ROWS_FIRST_SUMMARY`/`ROWS_NEXT_SUMMARY`,
  `buildPrintDoc()` 내부)는 CSS 행 높이(15mm) 기준 추정치이므로, 실제 화면에서 열어보고 페이지
  하단 여백이 어색하면 이 값들을 조정할 필요가 있을 수 있음.
