# 작업 진행 상황 (다음 세션 이어하기용)

마지막 업데이트: 2026-07-06

## 프로젝트 배경

기존 시스템(저장소 루트의 `code.gs` / `index.html`, 건드리지 않은 v4 원본)은 구글 시트에 바인딩된
Apps Script 웹앱으로, 코드 수정 시마다 재배포·재인증이 필요해 초보 관리자에게 어려웠음.

여러 방향(Supabase 이전 등)을 검토한 결과, 아래 **하이브리드 구조**로 결정하고 이 `sign/` 폴더에서
새로 구축 중 (v5):

```
[GitHub Pages]                     [각 기관의 구글 시트]
 index.html (공통 웹페이지)  ←fetch→  code.gs (JSON API, 최초 1회만 배포)
 · 관리자가 업데이트하면              · 연수설정 / 구성원명단 / 서명현황 /
   모든 기관에 자동 반영                미서명현황 / 사용설명서 시트
 · 재배포 불필요                     · 서명 PNG는 기관 드라이브에 저장
```

- 결정 이유: 학교뿐 아니라 여러 기관(예상 ~1,000곳)이 각자 독립적으로 쓸 걸 감안하면,
  기관별로 자기 구글 계정 안에서 완결되는 구조가 무료 사용량 한도·데이터 분리 면에서 유리함.
  Supabase 등 외부 서비스 계정 생성은 비개발자 다수에게 오히려 진입장벽이 될 수 있다고 판단.
- 이 판단·계산 과정의 상세 논의는 이전 대화 로그 참고 (사용량 추정, 요금제 비교 등).

## 폴더 구조

```
전자서명/
├─ code.gs, index.html          ← 구버전(v4) 원본, 건드리지 않음
└─ sign/                        ← 현재 작업 중인 v5
   ├─ code.gs        (831줄)    Apps Script 백엔드 — 각 기관이 최초 1회만 배포
   ├─ index.html      (2009줄)  GitHub Pages에 올리는 공통 웹페이지
   └─ README.md                저장소 설명 + 설치 가이드
```

## sign/code.gs 구조 (JSON API)

| 함수 | 역할 |
|---|---|
| `doGet(e)` | `?action=pageData` / `?action=records` 라우팅. 파라미터 없이 열면 "API 정상 작동" 확인 페이지(HTML) |
| `doPost(e)` | 서명 제출 처리 (`submitSignature`) |
| `getPageData()` | 기관명·오늘의 연수·부서별 구성원 목록·안내문·대표색상·PIN설정여부 반환 |
| `getSignatureRecords(title, date, pin)` | 서명등록부 출력용 기록 조회, PIN 검증 포함 |
| `submitSignature(payload)` | 중복 차단 → Drive에 PNG 저장 → 시트에 행 추가 + IMAGE 수식 |
| `generateAttendanceSummary()` | 시트 메뉴: 미서명 현황 집계 |
| `groupSortByTraining()` | 시트 메뉴: 서명현황 연수별 정렬 |
| `setupSpreadsheet()` | 시트 메뉴: 전체 시트 초기 생성 (연수설정/서명현황/구성원명단/미서명현황/사용설명서) |

### 시트/셀 상수 (전부 `code.gs` 상단에 정의)

```js
SHEET_CONFIG  = '⚙️ 연수설정'
SHEET_RECORDS = '📋 서명현황'
SHEET_STAFF   = '👥 구성원명단'   // (원래 '교직원명단'이었으나 전면 개칭)
SHEET_SUMMARY = '📊 미서명현황'
SHEET_GUIDE   = '📖 사용설명서'

ROW_ORG   = 2   // 기관명 (B2)
ROW_DEPT  = 4   // 부서 목록 (B4, 쉼표 구분)
ROW_PIN   = 18  // 출력 비밀번호 (B18, 텍스트)
ROW_NOTICE= 19  // 웹페이지 안내문 (B19, 텍스트)
ROW_COLOR = 20  // 대표 색상 (B20, **셀 배경색**을 채우기 색 도구로 칠함 — 텍스트 아님!)
```

## sign/index.html 주요 기능

- **연결 게이트**: 최초 접속 시 배포 URL 입력 → `fetch`로 검증 → `localStorage` 저장 →
  `?s=배포ID` 압축 공유링크 자동 생성
- **API 통신**: `google.script.run` 대신 `fetch` 사용. POST는 `Content-Type` 미지정(text/plain)으로
  보내 CORS preflight 회피 (Apps Script가 OPTIONS를 처리 못 하기 때문)
- **공유 링크 압축**: 배포 URL 전체(`?api=`, ~160자) 대신 배포 ID만(`?s=`, ~104자) 담음.
  이후 무료 단축 서비스로 추가 압축 시도: **da.gd → clck.ru** 순서 (is.gd/v.gd는 테스트 시점에
  서버 오류로 죽어있어서 제외함 — `makeShortUrl()` 함수, 실패 시 자동 폴백)
- **QR 자동 생성**: 공유 모달에 `api.qrserver.com`으로 QR 이미지 생성
- **서명등록부 출력**: 2인 1행 표, 번호는 왼쪽 열 세로 → 오른쪽 열 세로로 이어짐
  (`buildPrintDoc()`, 페이지당 첫 페이지 12명/이후 15명 — `ROWS_FIRST`/`ROWS_NEXT`),
  제목 한 줄(`OOO 서명등록부`), 서명 이미지 칸 꽉 채움, 하단 서명률 %
- **출력 비밀번호(PIN)**: 시트 B18 설정 시 출력 전 비밀번호 입력 모달, `sessionStorage`에 세션 동안만 보관
- **안내문 배너**: 시트 B19 → 헤더 아래 배너로 표시
- **대표 색상**: 시트 B20 **셀 배경색**을 그대로 읽어와 CSS 변수(`--brand` 등) 교체,
  서명 잉크색은 자동으로 어둡게 보정(`applyBrandColor()`)
- **연결 변경**: 공유 모달 안 "다른 배포 URL로 연결 변경" 버튼 → 확인 후 로컬 저장값 초기화
- **중복/대리서명 방지**: 서버 측 당일+연수+이름 중복 차단 + 클라이언트 `localStorage` 기기 잠금 (기존 v4 로직 유지)
- **데모 모드**: `?demo=1` 또는 `file://`로 직접 열면 가짜 데이터로 미리보기

## 검증 방식 (주의)

Chrome 브라우저 확장이 연결되지 않아 **실제 브라우저 렌더링/클릭 테스트는 못 했음**.
지금까지는 매 수정 후 `node -e "new Function(...)"`으로 JS 문법 오류만 확인했고,
`curl`로 단축 URL 서비스 응답만 직접 검증함. **실제 배포·연결·서명·출력 전체 플로우는 미검증.**

## 다음 세션에서 우선 확인할 것

1. **실제 엔드투엔드 테스트**: 구글 시트에 `code.gs` 배포 → GitHub Pages에 `index.html` 올리고
   실제로 연결·서명·출력까지 브라우저로 돌려보기 (Chrome 확장 연결 후 가능)
2. 기존에 "👥 교직원명단"으로 이미 초기설정된 시트가 있다면 시트 탭 이름을 "👥 구성원명단"으로
   바꾸거나 초기설정을 재실행해야 함 (사용자에게 이미 안내함)
3. 저장소 루트의 구버전 `code.gs`/`index.html`(v4)을 어떻게 할지 미정 — 그대로 둘지, 삭제할지,
   `sign/`을 루트로 승격할지 사용자와 상의 필요
