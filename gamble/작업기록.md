# 도박예방교육 체험 시뮬레이션 — 작업 기록

> 최종 갱신: 2026-07-14
> 대상: 청소년 도박예방 교육용. 실제 금전·실제 사이트 아님(상단 경고 배너 상시 노출).
> 백엔드·서버 없이 브라우저에서 단독 실행되는 웹 시뮬레이션. 오프라인 작동.

**⚠ index.html 파일 형식 주의**
초기에는 순수 단일 HTML 파일이었으나, 이후 **Claude 디자인으로 손본 뒤 아티팩트에서 export한 번들 파일**로 교체됨(약 1MB, 폰트 내장, **전체 HTML이 JS 문자열로 이스케이프**되어 저장 — `/`→`/`, `"`→`\"`). 따라서 손편집이 위험하며, 편집 시 이스케이프를 맞춰 Python 스크립트로 교체해야 함(§5 참고). **원본 소스의 진짜 출처는 claude.ai 아티팩트**이고, 아티팩트를 다시 export하면 로컬 수정이 덮어써짐.

## 1. 앱 개요

화려한 배너 → 가입 → 카지노 게임 → 초반 연승 → 잔액 소진 → 단계별 대출 →
사채 독촉·가족 붕괴 → 파산 → **각본이었음을 밝히는 각성(reveal) 화면**으로 이어지는
"불법 도박 피해 각본"을 1인칭으로 체험시키는 웹 시뮬레이션.

**전체 화면 흐름**: 인트로 → 배너 그리드 → 회원가입 → 카지노 → 파산 → 각성

## 2. 이번 세션에서 추가/변경한 내용

### ① 메신저 대화량 확대 + 연속 수신(몇 초 텀)
- 환영 메시지 3→**5개**, 각 대출 대화 **4개+**, 붕괴 시퀀스 9→**16개**로 확장
- 각 메시지에 `1.2~2.6초` 간격을 둬 순차 도착 → 알림이 쉴 새 없이 울리는 압박감
- 대출 직후 게임 중에도 다른 사람이 계속 압박 메시지를 보내는 **nudge** 추가
  (`scheduleNudge()` — 해당 라운드가 유지될 때만 발송)

### ② 등장인물(가족) 확대
- 기존 엄마·아빠 + **여동생·할머니·이모·담임선생님** 추가
- 붕괴 시퀀스에서 **사채 협박 ↔ 가족의 눈물**이 교차하도록 배치
- 말풍선 색상 구분: `friend`(파랑) `broker`(보라) `shark`(빨강/threat) `family`(초록) `teacher`(주황)

### ③ 친구에게 직접 돈 빌리는 단계 신규 추가
대출이 **눈덩이처럼 커지는** 다단계 구조로 재설계:
1. 내 돈 35만(30만+보너스 5만) 소진
2. **절친 민준** — 자기 돈 15만 직접 대출 (담주 20만 상환) ← **신규**
3. **같은반 승우** — "아는 형" 소개, 20만 대출 (담주 30만 상환)
4. **사이트 실장** — 50만 대출 + **신분증·부모님 연락처** 요구 (75만 상환)
5. 사채 독촉 → 붕괴

### ④ 사다리 애니메이션 + 게임 종류 추가 (총 4종)
- **사다리**: 결과만 나오던 것을 → 무작위 발판을 따라 **구슬이 실제로 내려가는 SVG 애니메이션**으로 교체.
  도착 칸에 당첨/꽝 표시. 패배 시 **옆 칸을 '당첨'으로** 둬 "아깝게 빗나간" 연출.
- **홀짝**: 기존 유지(주사위 굴림 애니메이션)
- **룰렛(빨강/검정)**: 숫자가 빠르게 돌다가 정해진 색에 착지 ← **신규**
- **슬롯(3릴)**: 릴이 순차 정지, 당첨 시 3개 일치 강조 ← **신규**

### ⑤ 연승 후 연패 중에도 1~2판 이기는 "유혹" 구조
- 라운드별 승패를 미리 정한 패턴 배열(`patterns`)로 제어. **간헐적 승리**를 심음:
  - `firstRun`: 6연승 후 지는 중에도 8·11·14번째 판을 이기게 함
  - 이후 대출 라운드도 초반 잠깐 승리 → 결국 전패
  - 배열 길이를 넘으면 무조건 패배 → 결국 잔액 0
- **슬롯 니어미스**(두 개만 일치 → "하나만 더 맞으면 대박") 토스트
- 연패 중 승리 시 **"거봐, 한 방이면 오르잖아"** 토스트로 재유입 유도

### ⑥ 출금 잠수/차단 시뮬레이션 (신규 요청)
- 상단바 **💵 출금** 버튼 추가
- 신청 시 "검토중" → **롤링 300% 미달·본인인증·계정점검** 등 사기 상투 사유로 항상 보류
  (달성률 표시가 **절대 100%에 도달하지 않음**)
- "관리자에게 문의" → 실장에게 메시지 → **타이핑 점만 뜨다가 무응답 → 잠수 → 연락 두절 → 계정 차단**
- 차단 후 출금 버튼은 **"⛔ 접속 차단 · 따놓은 돈이 사이트에 갇힘"** 표시
  → **돈을 따도 뽑을 수 없다**는 핵심 메시지 전달
- 각성(reveal) 화면 해설에도 반영

### ⑦ 각성(reveal) 화면 해설 갱신
간헐 보상·니어미스·다단계 대출(절친→형→실장)·출금 불가·가족 전체 협박 구조를 반영하도록 문구 수정.

## 3. 주요 기술 메모 (유지보수용)

- **상태 흐름(stage)**: `start → firstRun → loanCloseWait → secondRun → loanBrokerWait → thirdRun → loanSharkWait → fourthRun → collapse`
- **승패 각본**: `scripted()`가 `patterns[stage][stageBet]`를 반환. `stageBet`은 각 라운드 진입 시 0으로 리셋(가입 시, 각 대출 실행 함수 내부).
- **게임 공통**: 모든 게임이 같은 `scripted()` 결과 → `settle()`로 정산. 애니메이션만 게임별로 다름.
- **베팅 금액**: `#betRow` 하나를 4게임이 공유(`selBet` 전역).
- **휴대폰 메신저** *(§7에서 멀티룸으로 재작성 — 최신 구조)*:
  - 데이터: `rooms{id:{name,cls,sub,msgs[],unread,ts,time,actions}}` — 방 11개(가족·지인 8 + 총판/실장/사채 3). 가족·지인 방은 `seedHistory()`로 도박 전 일상 대화가 미리 채워짐.
  - 메시지: `say(roomId,kind,txt,delay)`(Promise, 순차 도착). `pushChat(type)`이 시나리오 실행, 붕괴는 `startCollapse()`→`showCollapseEnd()`(§10: 종료 시 강제 오픈+백스톱 타이머).
  - 버튼: `clearActions(id)`/`addAction(id,label,kind,fn)` — **방 id 명시 필수**(§9). `rooms[id].actions`에 저장돼 방 재입장 시 복원.
  - 뷰: `openPhone()`(목록)/`openRoom(id)`(대화)/`foldPhone()`(미니로 접기)/`dismissPhone()`(완전 숨김, §8). `addTyping()/removeTyping()`으로 잠수 연출.
- **출금**: `openWithdraw()` / `renderWithdraw(state)` — 상태 `form / processing / reject / blocked`. `wdBlocked`, `wdAttempts` 전역으로 관리.
- **정산(§8 변경)**: `tryBet()`이 **베팅 즉시 판돈 차감**, `settle()` 승리 시 `bet*2` 환급(화면상 "2배"), 패배 시 재차감 없음.

## 4. 향후 앱(구글 플레이) 전환 시 참고 — *웹 배포 반응 보고 결정 예정*

- **권장 방식**: **Capacitor**(HTML/JS를 앱에 내장, 서버 불필요, 오프라인 작동, iOS 확장 가능).
  대안: PWA→TWA(Bubblewrap/PWABuilder)는 호스팅이 필요해 이 앱엔 과함.
- **⚠ 최대 리스크 — 구글 플레이 도박 정책**: 교육용이라도 화면이 카지노/베팅이라
  "도박 흉내 앱"으로 오인·반려될 수 있음. 대비:
  - 교육용 배너 유지 + 스토어 제목·설명에 **"도박예방 교육"** 명시
  - 콘텐츠 등급 설문에서 "시뮬레이션 도박(실제 금전 없음)" 정직하게 선택
  - 학교/기관 배포면 **내부 테스트·조직 전용 배포**가 심사 부담이 훨씬 적음
- **필요 준비물**: 구글 플레이 개발자 계정($25 1회), 서명 키(keystore), 릴리스 AAB,
  아이콘·스플래시·스크린샷, 개인정보처리방침(수집 데이터 없으면 "수집 안 함" 명시).
- Capacitor 대략 순서:
  ```
  npm install @capacitor/core @capacitor/cli @capacitor/android
  npx cap init "도박예방체험" "kr.goedu.gamble.prevent"
  # index.html을 www/ 에 배치, webDir=www 설정
  npx cap add android && npx cap copy && npx cap open android
  ```

## 5. 각성 페이지 상담/신고 전화 확대 (추가 세션)

> 주의: 이 시점의 `index.html`은 Claude 아티팩트에서 export된 **번들 파일**(전체 HTML이 JS 문자열로 이스케이프됨, `/`->`\u002F`, `"`->`\\"`). 손편집이 위험해 Python 스크립트로 정확히 교체함.

- **1388** 청소년 상담전화 — 청소년 고민 24시간 상담(문자/카톡 가능)
- **1332** 금융감독원 불법사금융 신고 — 불법 사채·고금리·협박 추심·보이스피싱 피해
- **117** 학교폭력 신고센터 — 협박·금품 갈취·학교폭력 24시간 신고

## 6. 폰트 가독성 + 모바일 닫기 버튼 수정 (추가 세션)

> 주의: §5와 동일하게 번들 파일이라 손편집 위험. 번들 재export 시 덮어써짐 — 원본 아티팩트 소스도 함께 수정 필요.

### ① 인트로 메인 헤드라인 폰트 교체
- 대상: 인트로 화면 `<h1>` "불법 도박사이트의 각본을 / 직접 체험해봅시다"
- 문제: 기존 `Black Han Sans`는 초고중량·장체라 획이 붙어 가독성 저하
- 조치: `Gothic A1`(700/800/900) 사용, **weight 900**으로 볼드 임팩트는 유지하되
  자간(`letter-spacing .5px→1px`)·행간(`line-height 1.5→1.55`)을 넓혀 획 뭉침 완화
- 폰트 로드: 기존 preconnect 옆에 `fonts.gstatic` preconnect + Google Fonts `Gothic A1` 스타일시트 link 추가.
  오프라인/차단 시 `Noto Sans KR → 시스템 볼드`로 그레이스풀 폴백(굵기·가독성 유지)
- **주의**: 이 헤드라인만 교체했고 나머지 화면(총 ~94곳)은 여전히 `Black Han Sans` 사용. 통일 원하면 추후 일괄 교체 필요

### ② 넛지 메시지 후 닫기 버튼 누락 → 모바일 진행 불가 수정 (이후 §7에서 구조 자체가 멀티룸으로 재작성됨)
- 증상: 절친 민준의 "복구됨? 흐름 왔을때 멈추면…" 등 넛지 메시지 이후 휴대폰에 닫기 버튼이 안 떠서 모바일에서 진행 불가
- 원인: 이 계열 넛지는 전부 `scheduleNudge()`를 거치는데, 이 헬퍼가 **말풍선만 추가**하고
  다른 대화 흐름(`welcome`/`brokerGone` 등)이 붙이는 전체폭 `addAction('닫기',...)` 버튼을 안 만듦.
  → 우상단 `—`(btnFold, 26px) 아이콘만 남는데 모바일 노치 밑이라 사실상 닫기 불가
- 조치: `scheduleNudge()`가 말풍선 표시 후 `clearActions(); addAction('닫기','no',foldPhone)`를 붙이도록 수정.
  이 헬퍼를 타는 넛지 3곳(secondRun/민준, thirdRun/승우 형, fourthRun/실장) 일괄 적용
- 미검증: 브라우저 확장 미연결로 실제 모바일 클릭 재현은 못 하고 코드 흐름 분석으로 수정. 실기기 확인 권장

## 7. 메신저를 **사람별 대화방(멀티룸)** 구조로 재작성 (추가 세션, 2026-07-14)

> 주의: §5·§6과 동일하게 `index.html`은 번들 파일. 이번엔 편하고 안전하게 작업하려고
> **템플릿(JS 문자열로 이스케이프된 실제 앱 HTML)을 Python으로 디코드→편집→재인코드**했다.
> 재인코드 시 `<`를 전부 `<`로 이스케이프해 바깥 `<script>` 컨테이너가 조기 종료되지 않게 함(원본 번들러와 동일 방식). 왕복(JSON.parse) 일치 검증 완료.
> **롤백 백업: `index.html.bak`** (이번 작업 직전 원본). 아티팩트 재export 시 여전히 덮어써짐 — 영구화하려면 원본 아티팩트 소스도 같이 수정 필요.

### 문제
기존 메신저는 대화창이 **딱 하나**(`#chatBody`)뿐이라, 총판형·민준·승우·실장·엄마·아빠·여동생·할머니·이모·담임·사채가 **모두 같은 창**에 섞여 쏟아졌음. 헤더 이름(`chatApp`)만 바꿔가며 한 창을 재활용.

### 조치 — 카톡식 멀티룸
- **HTML**: `#phone` 흰 영역을 **목록 뷰(`#listView` → `#chatList`, `#listActions`)** + **개별 대화 뷰(`#chatView` → `#chatBack`·`#chatAvatar`·`#chatName`·`#chatSub`·`#chatTime`·`#chatBody`·`#chatActions`)** 두 개로 분리. `chatApp` 제거.
- **데이터 모델**: `rooms{id:{name,cls,sub,msgs[],unread,ts,time,actions}}` + `roomOrder`. 11개 방 정의(mom/dad/sis/grandma/aunt/teacher/minjun/seungwoo/chongpan/siljang/sachae).
- **예전(도박 전) 대화 씨앗**: 가족·지인 8개 방에 `seedHistory()`로 반가운 일상 대화 2~3개씩을 **읽음 상태**로 미리 채움(엄마 "저녁 차려놓을게", 민준 "pc방 ㄱ?" 등). 유입·추심 3개 방은 시나리오 진행 중 처음 등장.
- **핵심 함수**:

### ② "이기면 2배"인데 10만 걸고 이겨도 10만만 증가 → **판돈 차감 후 2배 지급**으로 수정
- 원인: `tryBet()`이 판돈을 **차감하지 않고** 금액만 반환. `settle()`이 승리 시 `money+=bet`(순이익 +판돈), 패배 시 `money-=bet`. 경제적으론 짝수배당(=2배)이 맞지만 **판돈 차감이 화면에 안 보여** "2배인데 왜 그대로냐"로 느껴짐.
- 조치(사용자 선택: *판돈 차감 후 2배*):
  - `tryBet()`: `var bet=Math.min(selBet,money); money-=bet; updateMoney(-bet);` — **베팅 즉시 판돈 차감**.
  - `settle()` 승리: `money+=bet*2; updateMoney(bet*2);` 라벨 `🎉 WIN 2배 +{bet*2}원`.
  - `settle()` 패배: 재차감 없이 `updateMoney(-bet)`(빨강 표시만). 판돈은 베팅 때 이미 나감.
  - **순경제 불변**: 승리 순변화 +판돈, 패배 순변화 −판돈으로 기존과 동일 → 각본상 결국 0원 흐름 그대로. 화면상 "베팅 −10만 → 당첨 +20만"으로 '2배'가 눈에 보임.
  - Node 하니스로 정산 경제 검증(일반 승/패, 올인 승/패, 라벨 문구 전부 통과).

### 검증 한계
- 여전히 브라우저 확장 미연결로 **육안/실기기 확인은 미완**. 로직은 `node --check` + DOM 스텁 하니스로 검증. 실기기에서 닫기 버튼 위치·터치 반응 최종 확인 권장.

## 9. 대출 확인 버튼이 안 보여 진행 불가 — 멀티룸 액션 버튼 버그 수정 (추가 세션, 2026-07-14)

> §7~§8과 동일 워크플로우. 롤백 백업 `index.html.bak` 유지(최초 원본). 아티팩트 재export 시 덮어써짐 주의.

### 증상 (사용자 리포트)
잔액 0원 → 절친 민준에게 돈 빌리는 대화까지는 뜨는데, **"15만원 빌리기 / 빌리지 않는다" 확인 버튼이 안 보여서** 다음 단계로 진행이 안 됨.

### 원인
§7에서 멀티룸으로 바꿀 때 `clearActions()`/`addAction(label,kind,fn)`이 **인자 없이 "지금 열려 있는 방(`activeRoom`)"을 암묵적으로 대상**으로 삼았음. 문제는 시나리오 메시지 4개가 도착하는 데 **약 6초가 걸리고**, 그 사이 사용자가 (예: 가족 메시지가 궁금해서) **다른 방으로 이동하면** `activeRoom`이 바뀌어버림. 그 결과 마지막 `.then()`에서 실행되는 `clearActions()`/`addAction()`이 **엉뚱한 방(예: 엄마)의 `actions`에 버튼을 기록**하거나, 목록 화면(`activeRoom===null`)에 있었다면 **아무 데도 기록되지 않고 소실**됨. 정작 `minjun` 방의 `actions`는 계속 빈 배열로 남아, 나중에 다시 들어가도 메시지만 보이고 버튼은 영영 안 뜸. (§8에서 휴대폰을 자유롭게 닫고 다른 대화를 볼 수 있게 만든 것과 정면으로 충돌하는 버그였음.)
- Node 하니스로 재현: `friendClose` 시나리오 진행 중 1.5초 시점에 `엄마` 방으로 이동 → 버튼이 `mom.actions`에 기록되고 `minjun.actions`는 `null`로 확인.

### 조치 — 방 id를 명시적으로 지정
- `clearActions(id)` / `addAction(id,label,kind,fn)`으로 **시그니처 변경**: 항상 `rooms[id].actions`를 직접 조작하고, `activeRoom===id`일 때만 `drawActions()`로 화면 갱신. 대상 방이 지금 안 보이고 있어도 **데이터는 정확히 그 방에 쌓이고**, 나중에 그 방을 열면 `renderRoom()→drawActions()`가 복원.
- **호출부 전체 업데이트**(약 20곳): `pushChat`의 welcome/friendClose/friendBroker/withdrawInquiry/brokerLoan 각 시나리오, 거절 후 2800ms 지연 강제버튼, `takeLoanClose/Broker/Shark`(클릭 핸들러 — 원래도 안전했지만 일관성을 위해 명시), `scheduleNudge` — 전부 대상 방 id(`'minjun'`/`'seungwoo'`/`'siljang'`/`'chongpan'`/`roomId`)를 직접 넘기도록 수정.
- `scheduleNudge`도 기존엔 `if(activeRoom===roomId)`일 때만 "닫기" 버튼을 기록해, 넛지가 울린 방을 안 보고 있으면 그 버튼이 영영 사라졌음 → 이제 **항상 대상 방에 기록**되고, 화면 갱신만 활성 방일 때로 제한.

### 검증
- Node 하니스로 버그 재현 확정 후 수정 → 재현 시나리오(다른 방 보던 중 메시지 도착) 재실행해 `minjun.actions`에 정확히 기록되고 재입장 시 버튼 2개 렌더됨을 확인.

- `go(id)` 함수(화면 전환 공용 함수, 모든 화면 전환이 이 함수를 거침)에 `badge.style.display = (id==='intro'||id==='ruin'||id==='reveal') ? 'flex' : 'none';` 한 줄만 추가 — 화면별로 각각 배지를 넣지 않고 한 곳에서 가시성 제어.
- 초기 로드 시(첫 `go()` 호출 전, `#intro`가 기본 `display:flex`인 것과 동일하게) 배지도 기본 인라인 스타일을 `display:flex`로 둬서 인트로 화면과 노출 시점이 어긋나지 않게 함.
- 스타일: 반투명 진한 배경(`rgba(20,20,26,.72)`) + blur + 흰 글씨 pill 형태 — 인트로/파산(어두운 배경)과 각성(밝은 배경) 양쪽에서 자체 배경으로 가독성 확보.

### 검증
- Python으로 `__bundler/template` JSON 문자열을 디코드 → 배지 마크업 삽입 + `go()` 수정 → 재인코드 후, **재인코드 결과가 원본과 동일한 이스케이프 규칙(`json.dumps(..., ensure_ascii=False)` 후 `<`→`<`)으로 원본과 바이트 단위 일치**함을 원본(수정 전)으로 먼저 확인.
- 패치 후 `__bundler/template` JSON 파싱 성공, `makerBadge` 마크업이 정확히 1곳에만 존재, `go()`의 조건식 문자열 존재 확인.
- 디코드된 HTML 내부의 인라인 `<script>`(로직 스크립트)와 최상위 번들 로더 스크립트 양쪽 다 `node --check`로 문법 검증 통과.
- **실기기/브라우저 육안 확인은 미완**(이 세션도 브라우저 확장 미연결). 특히 각성 화면(밝은 배경)에서 칩 대비, 모바일에서 칩이 하단 다른 버튼(예: 하단 고정 UI)과 겹치지 않는지 실기기 확인 권장.

## 12. 소액 배팅(1천원·3천원) 옵션 추가 — 청소년 소액 유인 문제점 반영 (추가 세션, 2026-07-15)

> §7~§11과 동일 워크플로우(번들 템플릿 디코드→편집→재인코드, 왕복 검증). 롤백 백업 `index.html.bak.before_betoptions` 추가.

### 문제의식 (사용자 지적)
실제 불법 도박사이트들은 배팅 최저액을 낮게 잡아 청소년도 "이 정도는 큰돈 아니니까" 하고 쉽게 참여하도록 유도함. 기존 배팅 버튼이 `10,000 / 20,000 / 50,000 / 100,000`원뿐이라 이 소액 유인 수법이 반영되지 않았음.

### 조치
- `buildBets()`의 배팅 버튼 배열을 `[10000,20000,50000,100000]` → **`[1000,3000,5000,10000,20000,50000,100000]`**로 확장(사용자 추가 요청으로 5,000원도 포함, `#betRow`는 4게임 공유, `flex-wrap:wrap`이라 버튼이 늘어도 레이아웃 깨지지 않음).
- 기본 선택값(`selBet`)은 20000 그대로 유지, 정산 로직(`tryBet()`의 `Math.min(selBet,money)`)도 값 크기와 무관해 별도 수정 불필요.

### 검증
- `__bundler/template` JSON 재인코드 후 파싱 성공, 새 배열 문자열 존재·구배열 제거 확인, 디코드된 인라인 스크립트 `node --check` 문법 통과.
- **실기기 육안 확인 미완**(브라우저 확장 미연결 지속) — 버튼 6개가 한 줄에 들어가는지, 모바일 폭에서 줄바꿈이 자연스러운지 실기기 확인 권장.
- 이후 5,000원도 추가 요청 받아 `[1000,3000,5000,10000,20000,50000,100000]`으로 재확장(동일 워크플로우로 검증).

## 13. 승패 각본 변경 — 뒤로 갈수록 승률 0%였던 것을 "최초 5판 승리 + 이후 25% 유지"로 수정 (추가 세션, 2026-07-15)

> §7~§12와 동일 워크플로우. 롤백 백업 `index.html.bak.before_scriptedchange` 추가.

### 문제의식 (사용자 지적)
기존 `patterns` 배열(§5에서 도입)은 스테이지별로 길이가 정해진 승패 배열이라, **배열 길이를 넘어서면 `pat[stageBet]`가 `undefined`→`false`가 되어 그 뒤로는 승률이 완전히 0%**가 됨(firstRun 17판, secondRun 10판, thirdRun 7판, fourthRun 5판 이후 전부 강제 패배). 사용자는 이 "뒤로 갈수록 무조건 패배"가 아니라, **최초 5회는 반드시 승리하고 그 다음부터는 (대출로 게임이 재개되어도) 승률이 대략 1/4로 계속 유지**되길 원함.
- 적용 범위는 두 옵션(①게임 전체에 한 번만 vs ②대출 라운드마다 재적용) 중 **① 게임 전체에 한 번만**을 사용자가 선택.

### 조치
- 스테이지별 `patterns` 객체(`firstRun/secondRun/thirdRun/fourthRun` 배열)와 각 배열 인덱스로 쓰이던 `stageBet`(스테이지 전환 시마다 0으로 리셋되던 변수)을 **완전히 제거**.
- `scripted()`를 게임 전체 누적 배팅 횟수인 `betCount`(기존에도 통계용으로 존재하던 전역 변수, 스테이지 전환과 무관하게 계속 누적됨) 기준으로 재작성:
  ```js
  function scripted(){
    betCount++;
    var win = (betCount<=5) ? true : (Math.random()<0.25);
    win?winCount++:loseCount++;
    return win;
  }
  ```
  → **전체 게임 통틀어 최초 5판은 무조건 승리**, 6판째부터는 대출로 게임이 몇 번을 재개되든 **매판 25% 확률로 승리**가 유지되어 0%로 떨어지는 구간이 사라짐. (다만 2배 배당에 25% 승률이면 기대값은 여전히 음수라 확률적으로는 결국 잔액이 바닥나는 시뮬레이션 취지는 그대로 유지됨 — Node로 10,000판 시뮬레이션해 6판째 이후 승률이 약 25.5%로 수렴함을 확인.)
  - `stage='secondRun'/'thirdRun'/'fourthRun'` 대출 단계 진입부에서 하던 `stageBet=0;` 리셋 3곳도 함께 제거(더 이상 쓰이지 않는 변수라 남겨두면 죽은 코드).

### 검증
- `__bundler/template` 재인코드 후 JSON 파싱 성공, `patterns`/`stageBet` 문자열이 전체 파일에서 완전히 사라졌음을 확인, 새 `scripted()` 본문 존재 확인.
- 디코드된 인라인 스크립트 `node --check` 문법 통과.
- `scripted()`와 동일한 로직을 Node로 별도 시뮬레이션(10,000회 호출)해 **처음 5회는 항상 true**, 이후 승률이 목표한 **약 25%로 수렴**함을 확인.
- **실기기 육안 확인은 미완**(브라우저 확장 미연결 지속) — 실제 플레이에서 대출 라운드 재개 후에도 이따금 승리가 나와 "0% 확정 패배"처럼 보이지 않는지, 각성 화면 해설 문구("초반 여러 판 → 무조건 연승", "가끔 한두 판 이기게 해줌")가 바뀐 메커니즘과 여전히 자연스럽게 맞는지 실기기 확인 권장(문구 자체는 수정하지 않았으며, 개념적으로는 여전히 들어맞음).
