# 테스트

빌드 도구도 의존성도 없습니다. node 만 있으면 됩니다.

```bash
node tests/matching.test.js
```

## 이 테스트가 지키는 것

`자율 · 진로 기록 모으기`에서 **업로드한 엑셀의 학생을 우리 반 명단과 맞추는 부분**입니다.
교사가 받는 전교생 취합 파일은 서식이 제각각인데, 열 하나가 달라지면 기록이 통째로 빠지면서
화면에는 `가져올 새 기록이 없습니다` 만 뜹니다. 그래서 실제로 실패했던 서식을 사례로 남겨 둡니다.

`tests/matching.test.js` 에 새 사례를 더할 때는, **먼저 재현되는 파일 서식을 사례로 적고**
그다음에 `index.html` 을 고치세요.

## 어떻게 돌아가는지

앱은 파일 하나(`index.html`)로 굴러가야 하므로 코드를 모듈로 쪼개지 않았습니다.
대신 `index.html` 안에서 **브라우저 API 를 쓰지 않는 순수 함수 구간**을 표시로 감싸 두고,
`tests/harness.js` 가 그 구간만 떼어내 node 에서 돌립니다.

```js
/* ===== @import-core:start ===== */
   ... 여기에는 document · window · state 를 쓰지 않는다 ...
/* ===== @import-core:end ===== */
```

구간에 브라우저 API 가 들어오면 테스트가 먼저 깨지므로, 순수하게 유지됩니다.
새 함수를 테스트하려면 그 구간 안에 두고 `tests/harness.js` 의 `CORE_NAMES` 에 이름을 더하세요.
