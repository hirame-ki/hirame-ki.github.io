# 규정나침반 — 개발 기획서

> 규정 문서를 올려두면, 관련 조항을 근거와 함께 찾아 답하는 브라우저 기반 RAG 도구.
> NVIDIA NIM 무료 API 사용 · 서버 불필요 · 완성된 단일 HTML 파일 존재(`index.html`).

---

## 1. 한 줄 정의

사용자가 자신에게 해당되는 규정·지침·매뉴얼(PDF/TXT)을 등록하면, 질문·사례를 입력했을 때 **관련 조항을 의미검색으로 찾아 근거와 함께 답변**하는 도구. AI가 판단하는 것이 아니라 **근거 조항을 가리켜주는** 보조 도구로 포지셔닝한다.

## 2. 대상 사용자

- 학교 교사 (특히 학폭·생활지도·학적 등 규정 확인이 잦은 업무 담당)
- 신규 발령자·업무 인수인계 상황
- 배포 방식: **BYOK (사용자가 각자 NVIDIA API 키 발급)** — 배포자 한도 소진 방지

## 3. 핵심 설계 원칙

1. **완전 클라이언트 사이드** — 서버·DB 없음. 모든 처리는 브라우저 안. API 키·문서 외부 전송 없음.
2. **근거 우선** — 모든 답변에 출처(파일·페이지·관련도%)와 원문 병기. "규정에 없으면 없다고 답한다."
3. **최종 판단은 사람 몫** — 답변 하단에 면책 안내 상시 노출. 행정·법적 처분은 원문·담당기구 검토 필수.
4. **1회 분석, 이후 저장** — 임베딩 결과를 localStorage에 저장해 재방문 시 재처리 없음.

## 4. 기술 스택

| 항목 | 선택 | 비고 |
|---|---|---|
| 구조 | 단일 HTML + 순수 JS | 빌드 과정 없음, GitHub Pages/Netlify 바로 배포 |
| PDF 파싱 | pdf.js 3.11.174 (CDN) | 브라우저에서 텍스트 추출 |
| 저장소 | localStorage | 임베딩 벡터 + 원문 청크 |
| API | NVIDIA NIM (OpenAI 호환) | `https://integrate.api.nvidia.com/v1` |

## 5. 사용 모델 (2026-07-28 갱신, index.html 실측)

| 용도 | 모델 문자열 | 근거 |
|---|---|---|
| 임베딩(검색) | `nvidia/llama-nemotron-embed-1b-v2` | 한국어 포함 26개 언어 검증, 최대 8192토큰, 무료 엔드포인트 |
| 답변 생성 | `CHAT_CHAIN` — `google/gemma-4-31b-it`(표시명 "Gemma 4 31B") → `openai/gpt-oss-120b` | 생기부돋보기 `test/model-bench.js`의 채점 결과를 그대로 따랐다(같은 NVIDIA 계정·같은 워커를 쓰므로 결과가 그대로 적용된다). gemma는 **일관성 5/6·과교정 0**, gpt-oss는 검출률이 9%p 높지만 **일관성 0/6**이라 같은 질문에 답이 매번 달라진다. 앞의 모델이 종료됐거나(404·410) **30초 안에 응답을 시작하지 못하면** 다음으로 넘어간다. `nemotron-3-super-120b-a12b`→`llama-3.3-70b-instruct`→`qwen3-next-80b-a3b-instruct` 순으로 교체해 왔는데, **2026-07-27 qwen3-next 수명 종료로 답변 생성이 통째로 멈춘 뒤** 단일 모델 대신 체인으로 바꿨다 |

- 임베딩 파라미터: `input_type: "passage"`(문서), `input_type: "query"`(질문), `encoding_format: "float"`
- 답변 생성 파라미터: `temperature: 0.1`, `top_p: 0.8`, **`seed: 12345`**, `max_tokens: 2048`, `stream: true`
  (사실 위주·보수적 설정 + 스트리밍 필수). `seed`는 2026-07-28에 추가 — 생기부돋보기에는 있었는데 여기만 빠져 있어
  같은 규정을 물어도 답이 조금씩 달라졌다.
- 임베딩 차원: 2048
- Qwen 계열은 한자·일본어 code-switching이 발생하기 쉬워, 시스템 프롬프트 최상단에 "순수 한글만" 규칙을 강제로 배치함(§8 참고).
  **Qwen은 2026-07-27 NVIDIA 카탈로그에서 사라졌지만** 이 방어 규칙은 그대로 둔다(다른 모델에서도 무해하고, `stripThink()`와 함께 이중으로 막는다).
- **NIM 카탈로그에 Gemini·GPT·Claude 계열은 없다.** 오픈웨이트 안에서 고를 수밖에 없다.
  Groq에는 `qwen3.6-27b`가 남아 있으나 무료 토큰 한도가 빠듯해 학급 단위 사용에 부적합하다고 판단해 NVIDIA를 유지한다(2026-07-28).
- **쓸 수 없다고 확인된 모델** — 다시 넣기 전에 읽을 것:
  · **NVIDIA 쪽 대기열 포화** — `ResourceExhausted: Worker local total request limit reached (1088/48)`.
    처리 슬롯 48개에 대기 1088건이라는 뜻으로, 모델이 느린 것이 아니라 줄이 밀린 것이다(우리 워커와 무관).
    순차 호출로도 90~120초를 넘긴다: `deepseek-ai/deepseek-v4-flash` · `z-ai/glm-5.2` · `mistralai/mistral-medium-3.5-128b`
  · **계정에서 접근 불가**(404 Not found for account): `moonshotai/kimi-k2.6` — 권한 문제라 시간이 지나도 그대로일 가능성이 크다
  · 답을 `delta.content`가 아니라 `reasoning`으로만 흘리고 `finish=length`로 끝남(워커를 거치지 않아도 동일):
    `nvidia/nemotron-3-nano-30b-a3b` · `openai/gpt-oss-20b` · `nvidia/nemotron-3-super-120b-a12b`

## 6. 무료 한도 대응

- NVIDIA 무료 티어: 약 **40 requests/분** (공식 SLA 아님, 커뮤니티 확인 기준선). 200 RPM 상향 신청 가능.
- **임베딩은 배치 처리**: 한 요청에 여러 청크(기본 32개) 전송 → 실제 요청 수 대폭 감소.
- 429 발생 시 자동 대기(4초) 후 재시도.
- 질문 1회당 요청 = 질문 임베딩 1 + 답변 생성 1 = **2 요청**. 개인 사용 시 한도 여유.

## 7. 데이터 파이프라인

```
[등록 단계 · 최초 1회]
PDF/TXT 업로드
  → pdf.js 텍스트 추출 (페이지 단위)
  → 청킹 (문장 경계 기준, 최대 700자, 페이지/단락 위치 기록)
  → 임베딩 배치 호출 (32개씩, input_type=passage)
  → {id, file, loc, text, vec} 형태로 localStorage 저장

[질의 단계]
질문 입력
  → 질문 임베딩 (input_type=query)
  → 저장된 전 청크와 코사인 유사도 계산
  → 상위 8개 추출 (유사도 > 0.15 필터)
  → 근거 조항 + 사례를 프롬프트로 조합
  → nemotron-3-super로 답변 생성
  → 답변 + 근거(출처·관련도·원문 펼침) 렌더링
```

## 8. 답변 프롬프트 구조 (system)

제공된 근거 조항만 바탕으로, 아래 3단 형식으로 한국어 답변:
1. **핵심 답변** — 결론 2~3문장
2. **규정과의 대조** — 사례가 규정에 부합/위반하는 지점, 각 항목마다 `(근거 N)` 표기
3. **필요한 절차·유의사항** — 규정상 절차·기한

근거에 없는 내용은 추측 금지 → "제공된 규정에서 확인되지 않습니다" 명시.

## 9. UI 사양 (2026-07-20 기준)

- **톤**: 딥네이비(#0b1a33~#16305c) + 골드(#c9a24b) — 공문서·법조 격식
- **폰트**: Pretendard / Noto Sans KR (궁서체 미사용)
- **구조**: 좌우 2열(≤900px 1열, 가운데 금색 세로 구분선)
  - **API 연결**: 카드가 아닌 모달(`#apiModal`) — 최초 접속 또는 저장키 자동연결 실패 시에만 노출. 우상단 고정 상태 칩(`#connPill`, `● 연결됨` + 모델명 + 해제 버튼)이 항상 표시
  - **왼쪽 열**: ① 규정 문서 등록(드래그앤드롭, 진행바, 문서별 체크박스·조항 수·삭제) → ② 규정 질의(예시 칩, 근거 조항 수 3/5/8 선택) → 질의 기록(클릭 복원, 개별 ×/전체 삭제, 내보내기)
  - **오른쪽 열**: 결과 안내(답변 전 점선 플레이스홀더) → 답변 카드(근거 조항 관련도%·원문 펼침, 다시 생성·복사 버튼, 하단 면책 안내) → 추가 질문 채팅(말풍선 UI, 근거+답변을 문맥으로 유지)
  - **좌하단 고정**: "사용법·팁" 칩 → 모달(엔비디아 NIM 소개로 신뢰도 안내 + 3단계 사용법 + 팁 + 주의사항)
  - **우하단 고정**: 제작자 칩(인스타그램 링크)
- 반응형(모바일 대응), 키보드 포커스 표시

## 10. 알려진 제약 / 배포 전 확인

- **스캔(이미지) PDF는 텍스트 추출 불가** → §11 로드맵 ① 참고.
- **구형 .hwp(바이너리)는 지원 불가** — 업로드 시 "한글에서 PDF·HWPX로 저장 후 재업로드" 안내 후 거부. HWPX(OWPML 표준, 한글 2014+)는 지원.
- **암호화된 HWPX**(배포용 문서로 저장된 경우)는 zip 내부가 잠겨 있어 추출 불가 — 일반 저장본이어야 함.
- 임베딩 배치 크기(`BATCH=32`)가 엔드포인트 제한에 걸리면 16으로 하향.
- 여러 파일을 한 번에 올릴 때 일부만 실패하면, 실패한 파일마다 사유를 개별 표시하고 성공한 파일 수도 함께 안내(요약 문구가 실패 사유를 덮어쓰지 않도록 처리, 2026-07-20 수정).
- 실제 규정 PDF/HWPX 1건으로 등록→질의 E2E 테스트 후 배포 권장 (HWPX는 표 포함 합성 파일로 추출 로직 단위 테스트 완료, 실제 한글 저장본 검증은 사용자 확인 필요).

## 11. 기능 로드맵 (2026-07-20 갱신)

### 반영 완료

- 좌우 2열 UI(왼쪽 등록·질의·기록 / 오른쪽 답변·추가 채팅), API 연결 모달 + 우상단 상태 칩
- 저장소 localStorage → **IndexedDB** 전환 (문서 임베딩 + 질의 기록)
- 답변 스트리밍(Cloudflare 524 대응), 429 자동 재시도, Cloudflare Worker 프록시(CORS 우회)
- **질의 기록**: 질문·답변·근거 원문·추가 채팅을 최근 50건 저장, 클릭 복원, 개별 ×/전체 삭제
- **추가 질문 채팅**: 근거+답변을 문맥으로 한 후속 질의 (한글 전용·추측 금지 규칙 동일)
- **DOCX·HWPX 업로드 지원** (mammoth.js / JSZip, CDN 지연 로드. 구형 HWP는 변환 안내)
- **기록 내보내기**: 전체 질의 기록을 마크다운(.md) 파일로 다운로드
- **다시 생성**: 같은 질문·근거로 답변만 재작성 (임베딩 재호출 없음, 요청 1회)
- **하이브리드 검색**: 코사인 유사도 + 키워드 일치 가산(최대 +0.15) — "제15조" 같은 조항 번호·고유명사 검색 보완
- **HWPX 표 중복 추출 버그 수정**: 표(`tbl`)가 바깥 문단 안에 중첩되는 OWPML 구조 때문에 표 내용이 두 번 추출되던 문제 → 텍스트 노드를 순서대로 훑으며 "가장 가까운 문단 조상"이 바뀔 때만 문단을 끊는 방식으로 수정. 표 포함 합성 HWPX 파일로 단위 테스트(6개 케이스) 통과 확인
- **업로드 실패 메시지 개선**: 여러 파일 중 일부 실패 시, 마지막 요약 문구가 실패 사유를 덮어쓰던 버그 수정 — 이제 파일별 실패 사유가 그대로 남고, 성공 건수도 "이번에 성공한 파일" 기준으로 정확히 표시(기존엔 기등록 문서 포함 누적 조항 수라 오해 소지 있었음)
- **좌하단 "사용법·팁" 칩 + 모달**: 우하단 제작자 칩과 대칭 위치. 클릭 시 엔비디아(NVIDIA) NIM 활용 소개(신뢰도 문구) + 3단계 사용법 + 실전 팁(질문 구체화, 근거 수 선택, 문서 체크박스, 질의 기록·내보내기, 다시 생성, 첫 응답 지연 안내) + 주의사항(개인정보 금지, 면책, 미지원 형식)

### 다음 업데이트 후보 (우선 검토)

1. **스캔본 PDF OCR** — 현재 스캔(이미지) PDF는 "추출할 텍스트가 없습니다"로 종료됨.
   - 방안 A: Tesseract.js(브라우저 내 OCR, 한국어 traineddata ~15MB, 느리지만 완전 클라이언트)
   - 방안 B: NVIDIA NIM의 OCR 모델(예: nemotron 계열 OCR) 프록시 경유 — 속도 유리, 문서가 서버로 전송됨(현재 임베딩과 동일한 고지 필요)
   - 진입점: `extractPdf()`에서 페이지 텍스트가 비었을 때 OCR 폴백 분기
2. **규정 간 충돌 비교 모드** — 문서 2개(예: 상위기관 지침 vs 내부 규정)를 지정해 같은 사안에 대해 다르게 규정한 지점을 찾는 모드.
   - 검색을 문서별로 각각 수행(topK 각각) → 프롬프트에 [문서A 근거]/[문서B 근거] 분리 주입
   - 기존 `buildAskMessages()` 구조 재활용, 답변 형식만 "일치점/차이점/해석 유의" 3단으로 교체
   - UI: 질의 카드에 "비교 모드" 토글 + 문서 2개 선택
