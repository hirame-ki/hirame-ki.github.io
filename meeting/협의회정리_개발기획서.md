# (가칭) 협의회 정리 도우미 — 개발 기획서

> 회의·협의회 녹음 파일을 드래그하면, 자동으로 전사→안건별 정리까지 해주는 브라우저 기반 도구.
> STT(한국어)와 정리(NVIDIA LLM)를 분리한 하이브리드 구조. **아직 미착수 — 기획 단계.**

---

## 1. 한 줄 정의

사용자가 회의 녹음 파일(mp3/m4a/wav 등)을 통째로 드래그하면, **코드가 알아서** 오디오를 분할·전사하고, 그 내용을 **안건 / 결정사항 / 후속조치(담당·기한)** 형태로 정리해주는 도구. 사용자는 파일을 자를 필요가 없다.

## 2. 대상 사용자 / 배포

- 부장회의·교과협의회·동학년협의회 기록 담당 교사
- BYOK (사용자 각자 API 키)
- **민감성 주의**: 회의 녹음은 참석자 동의·보안 이슈가 있음 → 배포용보다 **개인 업무용** 성격. 안내 문구에 "참석자 동의 하에 사용" 명시 권장.

## 3. 핵심 설계 원칙

1. **완전 자동 파이프라인** — 사용자 조작은 "파일 드래그" 한 번. 분할·전사·정리는 진행바 하나로.
2. **클라이언트 사이드 우선** — 오디오·전사문이 가급적 브라우저 밖으로 나가지 않도록 설계(단, STT 경로에 따라 예외 — 4번 참조).
3. **정리 결과는 편집 가능** — AI 정리는 초안. 사용자가 바로 수정·복사할 수 있게.

## 4. ⚠️ 가장 중요한 사전 결정: STT 경로

NVIDIA 카탈로그 조사 결과(2026-07 기준):

- **Parakeet 계열** = 빠르지만 **한국어 미지원**(영어·유럽어 중심). → 사용 불가.
- **Riva 사전학습 모델 / Whisper** = 한국어 지원. build.nvidia.com 스피치 카탈로그에 Whisper 계열 존재.
- 단, NVIDIA 스피치 API는 텍스트 LLM 같은 단순 REST가 아니라 **gRPC/특수 엔드포인트** 경향 → 브라우저 직접 호출이 까다로움. 착수 전 **실제 엔드포인트 형식·한국어 지원·무료 여부를 반드시 재확인**할 것.

### 권장: 하이브리드 구조

| 단계 | 경로 후보 | 비고 |
|---|---|---|
| STT(전사) | ① Groq Whisper API (한국어 우수, 무료 티어, REST 간단) **← 1순위 추천** | 기존 도구에서 Groq 사용 경험 있음 |
| | ② NVIDIA Whisper 엔드포인트 | 엔드포인트 형식 검증 후 판단 |
| | ③ 브라우저 내장 Web Speech API | 무료지만 긴 파일·정확도 한계 |
| 정리 | NVIDIA `nemotron-3-super-120b-a12b` 또는 `deepseek-v4-flash` | 긴 전사문 요약·구조화, 무료 |

> **결론**: STT는 한국어 품질이 검증된 경로(Groq Whisper 유력)로, **정리만 NVIDIA LLM**으로 하는 조합이 현실적. "NVIDIA만으로"를 고집하면 한국어 STT에서 막힐 위험이 큼.

## 5. 데이터 파이프라인

```
[입력]
녹음 파일 드래그 (mp3/m4a/wav)

[전처리 · 브라우저]
  → Web Audio API로 디코딩
  → 무음/길이 기준 청크 분할 (예: 5~10분 단위, 겹침 몇 초)
     └ 이유: 대용량 1시간 파일을 한 번에 못 올림 + 한도 관리

[STT · 순차 호출]
  → 각 청크를 STT API에 순서대로 전송
  → 전사문 이어붙이기 (타임스탬프 유지)
  → 진행바 갱신 (n/총 청크)

[정리 · LLM 1~2회]
  → 전체 전사문을 프롬프트로 → 안건별 구조화
  → (전사문이 매우 길면 청크별 요약 → 최종 통합의 2단계)

[출력]
  안건 / 논의요약 / 결정사항 / 후속조치(담당·기한) / 전체 전사문(접기)
  → 편집 가능 + 복사/내보내기
```

## 6. 정리 프롬프트 구조 (system, 초안)

회의 전사문을 아래 형식으로 한국어 정리:
- **회의 개요** — 일시·주제(추론 가능 범위)
- **안건별 논의** — 안건마다 핵심 논의 3~5줄
- **결정사항** — 확정된 내용만 불릿
- **후속조치** — `[담당] 할 일 (기한)` 형식, 명시 안 된 항목은 "담당 미지정" 표기
- 전사에 없는 내용 창작 금지. 불분명하면 "녹음에서 불명확" 표기.

## 7. 무료 한도 대응

- STT: 청크 순차 전송이라 분당 요청 수 낮음 → 한도 여유. Groq/NVIDIA 각 티어 확인.
- 정리: 1회(짧은 회의) ~ 수회(청크 요약+통합). 40 RPM 내 충분.
- 대용량 파일은 전처리에서 분할하므로 "파일 크기 초과" 실패 방지.

## 8. UI 사양 (규정나침반과 통일)

- 톤: 딥네이비 + 골드 (동일 브랜드 계열, @hirame.ki 도구군 일관성)
- 폰트: Pretendard / Noto Sans KR
- 구조: 3단계
  1. API 연결 (STT 키 + LLM 키 — 경로에 따라 1~2개) — 검증 후 `● 연결됨`만 표시
  2. 녹음 드래그 — 진행바(전사 n/N), 예상 소요 안내
  3. 정리 결과 — 섹션별 카드, 편집 가능, 전사 원문 펼침, 복사/내보내기
- 상단 또는 하단에 "참석자 동의 하에 사용" 안내

## 9. 알려진 리스크 / 착수 전 확인

1. **한국어 STT 경로 확정** — 착수 전 최우선. Groq Whisper vs NVIDIA Whisper 엔드포인트 실측.
2. **오디오 분할** — Web Audio API 디코딩은 매우 큰 파일에서 메모리 부담 → 스트리밍/샘플레이트 다운 검토.
3. **긴 전사문 컨텍스트** — 1시간 회의 전사는 토큰이 큼 → 청크 요약→통합 2단계 필요할 수 있음.
4. **화자 분리(diarization)** — 누가 말했는지 구분은 무료 STT로는 대체로 불가. 초기 버전은 화자 미구분으로 시작 권장.
5. **개인정보/보안** — 녹음·전사 처리 위치를 명확히. STT를 외부 API로 보내면 "완전 로컬"이 아님을 사용자에게 고지.

## 10. 단계별 제작 순서 (권장)

1. STT 경로 1개 확정 + 짧은 한국어 녹음으로 전사 품질 실측
2. 오디오 분할 + 순차 전사 파이프라인 (진행바)
3. 정리 프롬프트 + LLM 연결
4. 결과 편집/복사 UI
5. 규정나침반과 동일 톤으로 UI 마감
6. 실제 협의회 녹음으로 E2E 테스트

---

## 참고: 왜 규정나침반보다 뒤인가

규정나침반은 브라우저만으로 완결되고 한국어 텍스트 처리가 검증됐지만, 이 도구는 **한국어 STT라는 미검증 변수**가 있음. 그래서 규정나침반을 먼저 배포하고, 이 도구는 STT 경로 실측 후 착수하는 것이 안전함.
